00 · Header

T2 · Webex Calling

Survivability Gateway

In Active mode, endpoints register to the Webex cloud. When that path fails they register to a Survivability Gateway on the local network and keep basic calling. They return to the cloud after the connection has been back for at least 30 seconds. The gateway listens on port 8933 after mode webex-sgw. IOS XE Dublin 17.12.3 is the feature baseline. Hunt group, call forward, and auto attendant on the gateway start at IOS 17.18.2.

Room T2-R07Version v0.1last-verified: 2026-10-14Difficulty L3Est. time 80–100 minPrereq T2-R01, T2-R02Reading 20 min

Key takeaways

  • Each site that needs backup calling has a Survivability Gateway on the local network. Third-party devices are not supported. The gateway uses IPv4. [cite:1]
  • Platform maxima in the July 06, 2026 table include ISR 4321 at 50 endpoints and Catalyst Edge 8200-1N-4T at 2,500. Only the 4321 row states the minimum version, 17.12.3. The prose applies 17.12.3 to the feature set. [cite:1]
  • While in survivability mode you can configure up to 100 hunt groups with 32 users each. Weighted hunt routing is not supported in that mode. [cite:1]
  • Webex App shows a banner. Supported calls include internal extensions, PSTN, outgoing emergency, hold, transfer, inbound caller ID, and shared call appearance. Messaging and meetings are not supported. A Webex Calling call in progress is terminated when the site switches. [cite:2]
  • Colocation of a local gateway and a survivability gateway on one Cisco IOS box is described in an article dated November 20, 2024. Those sentences stay marked. re-check [cite:3]

01 · Executive summary

Five lines, then why it matters

  • Assign the service from Services > Calling > Managed Gateways. The hostname is the certificate FQDN. Devices register to the IPv4 address you enter. Download the template from Services > PSTN & Routing > Gateway configurations > Manage Gateways. [cite:1]
  • SIP TLS from devices uses source ports 5060–5080 toward gateway port 8933. Media uses device UDP 19560–19660 toward gateway UDP 8000–14198. The article says these defaults can be customized. [cite:1]
  • Certificates must be from a publicly known CA. Private or enterprise CAs are not accepted. Wildcard certificates are not supported. [cite:1]
  • Do not configure SIP bind under voice service voip. That causes registration failure. Shared line appearances count toward max-dn. Five phones sharing five DNs count as 25. [cite:1]
  • If you sign out of Webex App during survivability, you cannot sign in again until the network returns. When the outage ends, a call already up continues unchanged. [cite:2]
Why it matters. Survivability is local registration, not a second cloud. The hunt-group numbers from T2-R05 do not apply while the gateway is in that mode.

Glossary

Active mode
Endpoints register to the Webex cloud for SIP. [cite:1]
Survivability mode
Endpoints register to the local Survivability Gateway and use basic backup calling. [cite:1]
Survivability Gateway
An IOS XE router on the local network that takes registrations when the cloud path is down. [cite:1]
mode webex-sgw
The configuration mode after which the gateway listens on port 8933. [cite:1]
max-dn
The directory-number limit on the router. Shared appearances count. Five phones sharing five DNs count as 25. [cite:1]

Basic automatic call distribution on the gateway, with auto-attendant and one call-queue service. Colocation with a local gateway is not supported for this service. [cite:1]

06 · Config

Click paths and the router order

  1. If the gateway is not in Control Hub, enroll it first. The survivability article points at the enroll-IOS-gateways article. [cite:1]
  2. Open Services > Calling > Managed Gateways. Select the gateway. If the service is empty, click Assign Service and choose Survivability Gateway. [cite:1]
  3. Select one or more locations. Enter the certificate FQDN as the host name and the IPv4 address phones will register to. Click Assign. [cite:1]
  4. Download the template from Services > PSTN & Routing > Gateway configurations > Manage Gateways. [cite:1]
  5. On an ISR 4000, the article’s license example is license boot level uck9 and license boot level securityk9. Catalyst 8200 and 8300 examples use DNA Network Advantage and a crypto throughput. Catalyst 8000V examples use a throughput level. Throughput above 250 Mbps needs an HSEC license. [cite:1]
  6. Install a public CA certificate. Do not use a wildcard or a private CA. [cite:1]
  7. Apply the mandatory lines from the template, including mode webex-sgw. The gateway then listens on 8933. [cite:1]
  8. Leave SIP bind unset under voice service voip. Set max-dn to the platform maximum and count shared appearances. [cite:1]
  9. For external calls, add a VIC or a SIP trunk. PSTN during the outage depends on that path. [cite:1]

13 · Interview

Oral answers

30 seconds. Phones register to Webex until the path fails, then to a local Survivability Gateway on port 8933. They return after the link has been up for 30 seconds. The gateway is IPv4, IOS XE 17.12.3 or later, and it does not take third-party phones.

2 minutes. I assign the service on Managed Gateways with the certificate FQDN and the IPv4 address. I download the template, license the platform, and use a public CA without a wildcard. mode webex-sgw opens 8933. I do not set SIP bind under voice service voip. Shared appearances count toward max-dn. In that mode I can have 100 hunt groups of 32 users and I cannot use weighted routing. Webex App shows a banner and keeps basic calls, including outgoing emergency if the local PSTN path is up. Messaging and meetings stop. A call that is up when failover starts is torn down. A call that is up when service returns stays up. If the user signs out, they wait for the network.

30 seconds, scale. An ISR 4321 is 50 endpoints. A Catalyst Edge 8200-1N-4T is 2,500. Those numbers are registrations in the survivability table, not the Control Hub hunt-group caps.

2 minutes, what I will not merge. I will not quote the November 2024 colocation article without a re-check. I will not put survivability on a third-party SBC. I will not promise meetings. I will not treat a 10-second WAN recovery as the restore timer.

What you will say about PSTN. Internal extensions can work on the gateway. External calls need the VIC or the SIP trunk that is still available at the site.
