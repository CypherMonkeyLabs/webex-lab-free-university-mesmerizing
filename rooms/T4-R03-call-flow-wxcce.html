Call Flow Through WxCCE

T4-R03. How Unified CCE 15.0(1) routes a call, and how the Unified CVP Comprehensive model for ICME uses a Type 10 Network VRU. These guides are the heritage path behind the Enterprise track. They are not the multi-tenant Webex Contact Center flow.

Reading 16 minv0.1last-verified: TODOL4DraftStudy notes

Key takeaways

  • Three systems route a call: the routing client, the system software, and the peripheral that receives it. [cite:1]
  • Voice call types use dialed number, caller-entered digits, and calling line ID. Non-voice call types use Script Type Selector and two application strings. [cite:1]
  • If no destination is found, the system uses the default label on the dialed number, or returns an error. [cite:1]
  • CVP Comprehensive for ICME combines Call Director and VRU-Only, uses Network VRU Type 10, and connects with SendToVRU. [cite:2]

Prereq rooms: T4-R02 for Router and PG. Script nodes are T4-R04.

01 · TL;DR

A label goes back. The peripheral still has to agree.

  • Pre-routing comes from an IXC. Post-routing comes from the peripheral that already has the call. [cite:1]
  • A route is a skill target plus a service. Every call to a peripheral needs a service. [cite:1]
  • The routing client maps the label to busy, ring, an announcement, a scheduled target, or a trunk group and DNIS. [cite:1]
  • CVP Comprehensive call services are ICM, IVR, and SIP. Basic license level is wav and DTMF. Advanced adds ASR, TTS, and VXML Server applications. [cite:2]
  • Routing a Call was updated April 30, 2025. re-check CVP call-flow models were updated December 12, 2025. [cite:1] [cite:2]
Why it matters. People describe this as “the call hits the cloud and an agent answers.” The guides show a label, a trunk group, and a peripheral that must be programmed to the same skill target.

03 · Core

Call type, script, route, label

The Configuration Guide for Unified CCE Release 15.0(1), chapter Routing a Call, updated April 30, 2025, says three independent systems must work together: the routing client, the system software, and the peripheral that ultimately receives the call. The routing client requests a route, receives a response, and delivers the call. The system software picks a destination: an announcement, a scheduled target, or a specific target at a peripheral, represented by a trunk group and DNIS. A peripheral is an ACD, a PBX, or Unified CM. re-check [cite:1]

A routing request carries the dialed number, the calling line ID (also called ANI), and caller-entered digits. Pre-routing is an IXC asking for the initial destination. Post-routing is the peripheral asking to refine or redirect. [cite:1]

Two call-type grammars

Voice call types are categorized by dialed number, caller-entered digits, and calling line ID. The last two are optional. Non-voice call types, such as email and text chat, are categorized by Script Type Selector, Application String 1, and Application String 2. Call variables are not part of the call type definition, even when chat needs them. [cite:1]

The peripheral can disagree

After the label is delivered with a DNIS, the peripheral must recognize the trunk group and DNIS and map them to the same service and skill target the system software chose. The guide’s job is not finished when the Router returns a label. [cite:1]

StepWhat the guide says happensCite
Determine call typeMatch the qualifiers. Otherwise the routing-client default call type, then the general default.[cite:1]
Run scriptThe script scheduled for that call type at that time. Failure uses the default target on the DN.[cite:1]
Determine routeA skill target has a route: skill target plus service. A service target’s route must use that same service.[cite:1]
Peripheral targetTrunk group and optional DNIS. If several exist, the first one with a valid label for this routing client wins.[cite:1]
LabelFirst label valid for the routing client and dialed number. No call type, or no destination, uses the DN default label, else an error.[cite:1]

The routing client translates a label to busy, unanswered ring, an announcement, a scheduled target, or a peripheral target. For a normal or DNIS Override label that maps to a trunk group, it delivers the call and the DNIS. The routing client also has a maximum wait. If the system software is late or returns an error, the routing client takes its own default action. [cite:1]

The CVP 15.0(1) configuration guide, updated December 12, 2025, says the Comprehensive call flow model for ICME combines Call Director using SIP and the VRU-Only model. It provides initial prompt and collect, self-service IVR, queuing, and VoIP routing among UCCE and TDM agents. Basic port licensing supports wav files and DTMF. Advanced supports ASR/TTS servers and VXML Server applications. Unified CVP acts as the switch. Both the voice gateway and the Call Server have a switch leg and a VRU leg. A Type 10 Network VRU serves both legs. Use the SendToVRU node to connect the call to the Network VRU. The figures use solid lines for voice and dashed lines for signaling, and one physical gateway can serve both purposes. Call services for that model are ICM, IVR, and SIP. [cite:2]

SIP micro-application VoiceXML must return to the same Call Server as the switch leg. Comprehensive calls always use the same Call Server for the switch leg and the VRU leg. [cite:2]

06 · Config

Paths the articles name

  1. Define the voice call type with DN and, if you use them, CED and CLID. [cite:1]
  2. Define a default call type for the routing client and a general default. [cite:1]
  3. Schedule the script in Call Type Manager. The click path is in T4-R04. [cite:1]
  4. When the target is a service, keep the route’s service the same, or the statistics skew. [cite:1]
  5. Put a default label on the dialed number. [cite:1]
  6. For Comprehensive ICME, select ICM, IVR, and SIP on the Call Server, use a Type 10 Network VRU, and a SendToVRU node. [cite:2]
