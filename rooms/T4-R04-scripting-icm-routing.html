00 · Header

Scripting & ICM Routing

T4-R04. Script Editor for Unified CCE 15.0(1): create a routing script, schedule it on a call type, send the call to a Type 10 VRU, queue it, and run an external script. Updated April 30, 2025.

Reading 16 minv0.1last-verified: TODOL4DraftStudy notes

Key takeaways

  • File, New asks for a Routing script or an Administrative script. The canvas opens on a Start node. [cite:1]
  • You schedule the script in Script, Call Type Manager, on the Schedules tab. [cite:1]
  • A Type 10 Network VRU, typically Unified CVP, uses a two-step transfer. [cite:2]
  • The Queue node exits immediately. The script then needs a Run External Script so the caller hears treatment. [cite:2]

Prereq rooms: T4-R03 for call types and labels. T4-R02 for where Script Editor runs.

01 · TL;DR

Schedule the script, then give the VRU something to play

  • Call Type Manager has a Script tab, a Period tab, and an optional Description. [cite:1]
  • Run External Script, Play, Menu, Collect Data, or Queue before Send To VRU implies a Send To VRU for several VRU types. [cite:2]
  • If Run External Script fails, test Call.VRUStatus. The guide says 2 means the VRU is likely not functioning, and later nodes on that failure branch should be avoided. [cite:2]
  • A sample flow queues to three skill groups and plays an announcement every 30 seconds while a Wait node and a Run External Script alternate. [cite:2]
  • The guide was updated April 30, 2025. re-check [cite:2]
Why it matters. A script that queues and then ends will hold nobody. The guide says the Queue node does not send VRU instructions. Treatment is the next node.

03 · Core

A script does nothing until a call type schedule runs it

The Scripting and Media Routing Guide for Unified CCE Release 15.0(1), chapter Common Tasks, says Script Editor creates, modifies, and schedules routing scripts. File, New, or the New button, asks you to select a Routing script or an Administrative script. The Edit window opens with a Start node. File, Save asks for a script name. The guide’s header date is the same 15.0(1) book. The Network VRU chapter used for the node behavior was updated April 30, 2025. re-check [cite:1] [cite:2]

Scheduling associates the script with a call type: Script, Call Type Manager, Schedules tab, select the call type, Add. The Script tab selects the script. The Period tab defines when the schedule is effective. Description is optional. OK on both dialogs. [cite:1]

Type 10 is two transfers

If the Network VRU is Type 10, which the guide says is typically used only with Unified CVP, the Router uses a two-step transfer. The first moves the call to Unified CVP. The second automatic transfer sets up a VRU leg that uses the VXML Gateway or Cisco Virtualized Voice Browser for IVR treatment. The purpose is to simplify Comprehensive call flow configuration. For calls that are front-ended by Unified CVP, only a single automatic transfer from the switch leg to the VRU leg occurs. For calls from Unified CM, the correlation ID is added to the end of the Type 10 transfer label. [cite:2]

Queue is not the audio

The Queue node does not send instructions to the VRU. On success it exits immediately and the call is assumed to be at the VRU. The script should continue with Run External Script so the VRU plays music or an announcement until an agent is free. The sample call flow queues the call for three skill groups, then cycles Wait and Run External Script so the caller hears an announcement every 30 seconds. When an agent is free, the call leaves queue, script execution ends, and the call is delivered. Do not use Route Select in that cycle. [cite:2]

NodeWhat the chapter saysCite
Send to VRUValid for Types 3, 5, 6, 7, and 10. Include it as a visual aid even when an earlier node implies it.[cite:2]
Implicit Send to VRURun External Script, Play, Menu, Collect Data, or Queue before Send to VRU assumes the send for Types 3, 5, 6, and 7.[cite:2]
Run External ScriptValid for all VRU types. Success and failure branches. If the call is not yet at a VRU, CCE sends it.[cite:2]
QueueExits immediately. Does not instruct the VRU.[cite:2]
Queue to Precision QueueAlso exits to a Run External Script for treatment. Can queue the same call to other targets.[cite:2]

On the failure branch of Run External Script, test Call.VRUStatus. If the value is 2, the VRU is likely not functioning, so the script should avoid more Run External Script nodes on that branch. The guide also says the last Send To VRU or Translation Route to VRU failed if the routing client did not respond within 20 seconds, or the last Run External Script failed because the script’s timeout expired. Uninterruptible nodes, including an uninterruptible external script, make the CallRouter wait. The Wait node and an interruptible Run External Script are interruptible. Every other node is uninterruptible. Calls can be routed when they reach an interruptible node. [cite:2]

Find Nodes can search by section, node type, or string. That is how you locate a node in a large script. [cite:1]

04 · Ecosystem

Ecosystem and sister technologies

ICM scripts schedule against call types. Webex Contact Center flows and Connect digital flows are different tools.

30 seconds

Interruptible node
Wait, and an interruptible Run External Script. Other nodes are uninterruptible. [cite:2]
Queue node
Marks the call queued and exits. It does not play audio. [cite:2]

06 · Config

Paths the articles name

  1. File > New. Choose Routing script. Save and name it. [cite:1]
  2. Script > Call Type Manager > Schedules > Add. Set the script and the period. [cite:1]
  3. Place Send to VRU, or know which earlier node implies it. [cite:2]
  4. Queue to Skill Group or Precision Queue, then Run External Script on the success branch. [cite:2]
  5. On failure, branch on Call.VRUStatus 2. [cite:2]
  6. Use Find Nodes when the script is too large to scan. [cite:1]
