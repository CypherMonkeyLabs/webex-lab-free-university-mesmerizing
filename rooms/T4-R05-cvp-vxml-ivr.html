T4 · Webex Contact Center Enterprise

CVP & VXML IVR

Unified Customer Voice Portal is the VoiceXML IVR in the Unified CCE design guides. This room keeps the standalone model, the comprehensive model, and the Webex CCE hosting sentence in separate boxes.

Room T4-R05 Version v0.1 last-verified: TODO Difficulty L3 Est. time 80–100 min Prereq T4-R01 Reading 20 min

Key takeaways

  • Standalone without reporting does not require a Call Server or a Reporting Server. Standalone with reporting requires both. [cite:1]
  • In the standalone model the required pieces are the VXML Server, Call Studio, and a gateway, unless reporting is on. [cite:1]
  • Comprehensive is the only CVP call flow the Solution Design Guide allows inside a Reference Design. Standalone is a non-reference flow. [cite:3] re-check
  • A comprehensive call has a switch leg on the ingress gateway and a VRU leg on Cisco VVB. Micro-application VoiceXML returns only to the same Call Server as the switch leg. [cite:1]

01 · Executive summary

Five lines, then why it matters

  • The VXML Server is a J2EE-compliant application server for dynamic VoiceXML applications. It can be installed without the Call Server. [cite:2]
  • Standalone without reporting uses the VXML Server (Standalone) option. Standalone with reporting uses the VXML Server option and adds a Call Server and a Reporting Server. [cite:1]
  • Comprehensive combines Call Director using SIP and VRU-Only. Basic ports play .wav files and collect DTMF. Advanced ports add ASR, TTS, and VXML Server applications. [cite:1]
  • From Unified CVP 11.5(1), the Call Server IVR service lives on the VXML Server, which builds the VXML pages for the microapplications. [cite:2]
  • The January 2025 Webex CCE note says custom CVP applications can be hosted on Webex CCE. That sentence is older than 12 months. [cite:5] re-check
Why it matters. Interviews fail when a standalone self-service app is drawn as a comprehensive queue, or when Flow Designer is named as the Unified CVP script tool. The configuration guide names Call Studio. The build-and-manage article names Flow Designer for multi-tenant Webex Contact Center. [cite:1] [cite:6]

03 · Core concepts

What the CVP 15 guide separates

VXML Server

A J2EE-compliant application server for creating and deploying dynamic VoiceXML applications. The standalone install omits the Call Server and is built for self-service. [cite:2]

Call Studio

Applications are created in Call Studio and deployed to the VXML Server. The configuration guide’s standalone procedure says to deploy the application as a zip file. CVPSNMPLogger is enabled by default on a new deployed application. [cite:1]

Two standalone variants

Without reporting, choose VXML Server (Standalone) in the Operations Console. With reporting, choose VXML Server, and the Call Server routes messages between components. Calls arrive through Cisco VVB and run VoiceXML on the VXML Server. Cisco VVB performs ingress. [cite:1]

Reference Design rule

The Solution Design Guide, updated March 15, 2025, says the Comprehensive call flow is the only one you can use in a Reference Design. Standalone VXML Server, Call Director, and VRU-Only are listed as non-reference alternates. [cite:3] re-check

Same Call Server

SIP calls that use Unified CVP micro-applications use the IVR Service of the Call Server that holds the switch leg. VoiceXML fetches go to that Call Server. Micro-application VoiceXML traffic must return only to the same Call Server. Comprehensive calls always use the same Call Server for the switch leg and the VRU leg. [cite:1]

06 · Config

Operations Console steps the guide names

  1. Decide the model. Standalone without reporting: Device Management path that selects VXML Server (Standalone). Standalone with reporting: VXML Server, plus a Call Server and a Reporting Server. [cite:1]
  2. For a Cisco VVB standalone deployment, define the VXML Server applications, configure the base gateway and VVB settings, and configure the dial-peer that triggers the self-service application. [cite:1]
  3. Create the application in Call Studio and deploy it to the VXML Server. The procedure says to deploy it as a zip file. [cite:1]
  4. Enable loggers in Call Studio. CVPSNMPLogger is on by default for a new deployed application. [cite:1]
  5. If the script must ask ICM for a label, use the ReqICMLabel element. Pass data in Peripheral Variables 1–10. The guide says those values are taken as is. [cite:1]
  6. For comprehensive ICME, configure the IVR service to work with Cisco VVB. Use SendToVRU. Keep both legs on the same Call Server. [cite:1]
  7. IVR settings for microapplications are on the VXML Server IVR tab, because the IVR service moved at 11.5(1). [cite:2]

09 · Self-question ladder

Twelve rungs

L0What is the VXML Server?

A J2EE-compliant application server for dynamic VoiceXML applications. It can run without the Call Server. [cite:2]

L1What breaks if you want reports and you picked VXML Server (Standalone)?

That option does not require a Call Server or a Reporting Server. Reporting needs the other option plus both servers. [cite:1]

L1Which three components does standalone require before reporting is added?

VXML Server, Call Studio, and a gateway. [cite:1]

L2What are the four steps in the standalone VVB figure?

PSTN or provider to the ingress gateway or CUBE. SIP invite to VVB. HTTP request to the VXML Server. VoiceXML back to VVB, optionally pointing at ASR, TTS, or .wav files. [cite:1]

L2What does each comprehensive leg do?

Switch leg: gateway does TDM-to-VoIP and call switching. VRU leg: Cisco VVB does VRU voice treatment. [cite:1]

L2Why must micro-application VoiceXML return to one Call Server?

The IVR Service of the Call Server that has the switch leg receives the fetches. The guide says the traffic must return only to that Call Server. [cite:1]

L3How do you prove a Reference Design is using the allowed CVP flow?

The design guide says Comprehensive is the only call flow you can use in a Reference Design. Standalone is listed under non-reference. [cite:3] re-check

L3Basic ports are quiet when the caller speaks. What do you check?

Basic supports .wav and DTMF. ASR and TTS are Advanced. [cite:1]

L3Where did the Call Server IVR service go?

To the VXML Server, beginning with 11.5(1). Microapplication pages are created there. [cite:2]

L4How is comprehensive different from multi-tenant Flow Designer?

This room’s script tool is Call Studio, and the queue handoff the guide names is SendToVRU. Flow Designer is the Webex Contact Center flow article. [cite:1] [cite:6]

L4What does the January 2025 Webex CCE note add?

Custom code applications can be hosted on Webex CCE, including a move of CVP applications that use VXML and Call servers. The note is older than 12 months. [cite:5] re-check

L5What constraint stops you from treating standalone as a full contact-center queue?

The design guide describes standalone as a VRU with no integration to Unified CCE for queuing control or subsequent call control, and it excludes that flow from Reference Designs. [cite:3] re-check

13 · Interview

Oral answers

30 seconds. Unified CVP has a standalone self-service model and a comprehensive switch model. Standalone needs the VXML Server, Call Studio, and a gateway. Reporting adds a Call Server and a Reporting Server. Comprehensive is the Reference Design flow.

2 minutes. In the standalone figure the call hits an ingress gateway or CUBE, the gateway sends a SIP invite to Cisco VVB with the trigger, VVB requests VoiceXML over HTTP, and the instructions can point at ASR, TTS, or .wav files. Comprehensive has a switch leg on the gateway and a VRU leg on VVB. Micro-application VoiceXML returns only to the Call Server that owns the switch leg. Type 10 and SendToVRU are the ICME names. Basic ports are .wav and DTMF. Advanced adds speech and VXML applications.

30 seconds, the tool. I build the app in Call Studio. Flow Designer is the multi-tenant Webex Contact Center canvas, not this chapter.

2 minutes, the cloud sentence. A January 2025 what’s-new line says Webex CCE can host custom CVP applications. I keep that sentence marked re-check, and I do not let it erase the CVP 15 call-flow chapter. Hybrid IVR, from July 2023, is the note that mixes on-premises ASR/TTS with Dialogflow CX. That date is also re-check.

What you will not say. You will not size a Reference Design from the non-reference limits table. The design guide says those limits apply to non-reference designs only.
