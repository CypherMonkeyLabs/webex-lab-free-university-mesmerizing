00 · Header

T4 · Webex Contact Center Enterprise

Finesse Desktop & Gadgets

Cisco Finesse is the browser desktop in the Unified CCE and Webex CCE guides. The layout is XML. Failover is a CTI reconnect, not a gadget refresh.

Room T4-R06 Version v0.1 last-verified: TODO Difficulty L3 Est. time 80–100 min Prereq T4-R01 Reading 20 min

Key takeaways

  • A gadget is an OpenSocial XML document. Manage Desktop Layout uploads the XML that places gadgets for agents and supervisors. [cite:1]
  • Gadgets on the Finesse server use a relative path. Gadgets on another server use an absolute URL. Third-party files uploaded to the server are referenced as /3rdpartygadget/files/.... [cite:2] [cite:3]
  • CTI failover requires Unified CCE in duplex mode and a B-side CTI host and port. During failover Finesse is OUT_OF_SERVICE and returns 503. [cite:4]
  • A and B side CTI servers are mandatory for a production Unified CCE and Finesse deployment. The same Agent PG peripheral ID is used on both sides. [cite:5]

01 · Executive summary

Five lines, then why it matters

  • Finesse gadgets are applications inside one desktop. Third-party gadgets can live on the 3rdpartygadget web application or on an external server. [cite:1]
  • REST calls from a gadget to an external service are proxied through Shindig. The gadget still has to authenticate to that third-party service itself. [cite:1]
  • The layout XML has an Agent role and a Supervisor role. A supervisor tab is added under the Supervisor tag. [cite:1]
  • Finesse misses failover detection after three missed CTI heartbeats. The heartbeat interval is five seconds. [cite:4]
  • If a desktop client’s reconnect takes longer than 2 minutes, Finesse signs the agent out. [cite:6] re-check
Why it matters. Multi-tenant Agent Desktop layouts are T3-R04. This room is the Finesse administration guide: XML layout, 3rdpartygadget, and CTI failover. Mixing the two desktops produces a design you cannot click.

03 · Core concepts

XML, proxy, and duplex

OpenSocial gadget

Cisco Finesse is an OpenSocial gadget: an XML document that defines metadata for an OpenSocial gadget container. Gadgets are the applications placed on the desktop so the agent can service calls inside one application. [cite:1]

Shindig proxy

Gadgets can make REST requests to external servers through the Cisco Finesse JavaScript library. To avoid browser cross-origin issues, those requests are proxied through the Shindig web application. Third-party gadgets must implement their own authentication for third-party REST services. [cite:1]

Production CTI pair

The B-side host and port fields are not shown as required in the UI. The administration guide still says A-side and B-side CTI servers are mandatory for a production deployment of Unified CCE and Cisco Finesse. The CTI server runs on the PG. [cite:5]

Test Connection

If Test Connection succeeds for one side and fails for the other, the guide calls that a valid configuration because the CTI server works active-passive and the inactive node refuses the CTI port. Success on both sides at once is an error to investigate. Test Connection does not prove the peripheral is online. It validates that the peripheral is configured in Unified CCE. [cite:5]

04 · Ecosystem

What sits beside the desktop

Glossary

Finesse
The OpenSocial gadget container documented in the Cisco Finesse Administration Guide, Release 15.0(1). [cite:1]
Manage Desktop Layout
The administration gadget used to upload the XML layout for agents and supervisors. [cite:1]
3rdpartygadget
The web application on the Finesse server that hosts uploaded third-party gadget files. [cite:1]
Shindig
The backend that proxies gadget REST calls so the browser does not make a cross-origin call directly. [cite:1]
CTI server
Runs on the peripheral gateway. Finesse is configured with an A side and a B side. [cite:5]
Peripheral ID
The Agent PG routing client ID. The guide says it should be the same value for the A-side and B-side CTI servers. [cite:5]
OUT_OF_SERVICE
Finesse state while CTI failover is in progress. [cite:4]
IN_SERVICE
Finesse state after it reconnects to a CTI server and will again answer clients and publish events. [cite:4]
Manage Digital Channels
A gadget path the default layout comments include for digital channels. The what’s-new page points at the gadget user guide. [cite:1] [cite:7]
FIPPA
Finesse IP Phone Agent. The March 2022 VPN-less note says FIPPA is not supported on that internet path. [cite:7] re-check
Multi-tenant Agent Desktop
The Webex Contact Center desktop in T3-R04. It is not this XML layout. [cite:8]
Conference caveat
An agent on a conference with devices that are not other agents or supervisors can see unpredictable desktop notifications across a failover. Phone operations can continue. The desktop returns to usual after the agent drops the conference. [cite:4]

06 · Config

Settings you can cite

  1. Open Manage Desktop Layout and upload an XML file. Keep an Agent role block and a Supervisor role block. [cite:1]
  2. For a gadget file you uploaded to the Finesse server, add a relative path under /3rdpartygadget/files/. [cite:3]
  3. For a gadget on another host, use a fully qualified URL. [cite:2]
  4. On the primary Finesse server, open Contact Center Enterprise CTI Server Settings. Enter A-side host and port, B-side host and port, and the Agent PG peripheral ID. Use the same peripheral ID on both sides. [cite:5]
  5. The CTI host is typically the PG, because the CTI server runs on the PG. B-side port accepts 1 through 65535 and must match the CTI server setup. [cite:5]
  6. Use Test Connection. One side succeeding is valid. Both succeeding together is a problem to fix. The test does not prove the peripheral is online. [cite:5]
  7. After any CTI settings change, restart Cisco Finesse Tomcat on all nodes. Do that when agents are signed out. They must sign in again after the restart. [cite:5]

09 · Self-question ladder

Twelve rungs

L0What is a Finesse gadget?

An OpenSocial XML document placed on the Finesse desktop. [cite:1]

L1Why does the layout have two role blocks?

The XML defines the desktop for agents and for supervisors. Supervisor-only tabs go under the Supervisor tag. [cite:1]

L1What fails if a third-party gadget assumes Finesse will log it into the CRM?

The guide says the gadget must implement its own authentication for third-party REST services. Shindig only proxies the call. [cite:1]

L2How does a gadget file on the Finesse server get referenced?

A relative path. The third-party chapter’s example is /3rdpartygadget/files/HelloWorld.xml. [cite:3]

L2When is an absolute URL required?

When the gadget is hosted on a server other than the Finesse server. [cite:2]

L2What are the duplex prerequisites for CTI failover?

Unified CCE in duplex mode, and the B-side CTI host and port configured in Finesse administration. [cite:4]

L3How do you prove a 503 is failover rather than a bad gadget?

Finesse is OUT_OF_SERVICE and does not send events. After IN_SERVICE it publishes the last call control, call data, and agent state. [cite:4]

L3Why can Test Connection fail on one side and still be valid?

CTI is active-passive. The inactive node refuses the CTI port. Both sides succeeding together is the error case. [cite:5]

L3What does a CTI settings change do to signed-in agents?

You restart Finesse Tomcat on all nodes. Agents sign out and sign in again. [cite:5]

L4How is this desktop different from multi-tenant Agent Desktop?

This room follows the Finesse administration guide. Multi-tenant Agent Desktop is a different product surface, covered in T3-R04. [cite:8]

L4What does the March 2022 VPN-less note exclude?

FIPPA, and multiple devices accessing the desktop through NAT. The note is older than 12 months. [cite:7] re-check

L5What constraint stops you from promising every conference will redraw cleanly after failover?

The failover chapter says conferences that include devices not associated with another agent or supervisor can produce unpredictable desktop notifications. The phone can still be used. The desktop returns to usual after the agent drops the conference. [cite:4]

13 · Interview

Oral answers

30 seconds. Finesse is an OpenSocial desktop. I upload one XML layout with an Agent role and a Supervisor role. Gadgets on the server use a relative path under 3rdpartygadget. Gadgets elsewhere use an absolute URL.

2 minutes. CTI failover needs duplex Unified CCE and both CTI sides. The CTI server runs on the PG, and both sides use the same peripheral ID. Three missed five-second heartbeats, or a dead socket, moves Finesse to OUT_OF_SERVICE. Clients get 503 and no events. Finesse alternates servers until one connects, then publishes the last call and agent state. A call that begins and ends inside that window is not published. Test Connection may fail on the passive side. Both sides succeeding at once is the case I investigate.

30 seconds, auth. Shindig proxies the REST call. The gadget still logs into the third-party service itself.

2 minutes, timers I date. The heartbeat and the 503 are in the administration guide updated December 12, 2025. The two-minute desktop sign-out is in the Solution Design Guide updated March 15, 2025, so I mark it re-check. The VPN-less exclusions for FIPPA and NAT are a March 2022 what’s-new note, also re-check.

What you will not say. You will not configure this XML from the multi-tenant Agent Desktop screen. That desktop is a different product.
