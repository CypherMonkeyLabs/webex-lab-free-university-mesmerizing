00 · Header

T4 · Webex Contact Center Enterprise

Sizing & HA

Unified CCE high availability is Side A and Side B for redundancy, not for load-balancing. A Webex CCE what’s-new sentence about 48,000 agents is a different number from the Finesse 2,000-user line in the design guide.

Room T4-R08 Version v0.1 last-verified: TODO Difficulty L3 Est. time 90–110 min Prereq T4-R01 Reading 22 min

Key takeaways

  • Side A and Side B are redundant. Either side can run the full load. Both sides process every call. Logically there is one Router. [cite:1] re-check
  • Device majority: Side A needs at least half of its enabled PGs. Side B needs more than half. [cite:1]
  • Private and public networks are separate physical networks. QoS is required on every private network. [cite:1]
  • One Finesse cluster on an Agent PG supports a maximum of 2,000 users across both servers. A January 2025 Webex CCE note says 48,000 concurrent agents and 300 calls per second on a single tenant. [cite:1] [cite:2]

01 · Executive summary

Five lines, then why it matters

  • The private network carries synchronization and MDS traffic. The public network carries traffic between Central Controllers and PGs and is the alternate path that distinguishes a component failure from a network failure. [cite:1]
  • Never split one component’s private traffic onto a low-priority path and a high-priority path. That disables failover. [cite:1]
  • On a private-network failure, a router with device majority goes isolated-enabled and keeps handling traffic. Without majority it goes isolated-disabled and stops. [cite:1]
  • If the private network stays down longer than the 14-day retention of Config_Message_Log, logger resynchronization uses Unified ICMDBA. [cite:1]
  • Where possible, do not run devices, call processing, or CTI Manager on the Unified CM publisher. PGs are hot standby: only one side is active. [cite:1]
Why it matters. People add Side A and Side B and then load-balance calls across them. The design guide says the opposite. People also paste 2,000, 12,000, and 48,000 into one sentence. Those numbers live on different pages.

03 · Core concepts

Redundancy, majority, and three different caps

Not load-balancing

The two sides are for redundancy, not load-balancing. Either side can run the full load. Sides A and B perform the same messages and produce the same result. During a failure the surviving Router takes the call midstream without user intervention. [cite:1] re-check

PG hot standby

Only one PG is active and controlling the peripheral. When the active side fails, the surviving side takes over and runs stand-alone until the other side returns. Then the PGs return to redundant operation. [cite:1]

Device majority is asymmetric

Side A has majority when it can communicate with at least half of its total enabled PGs. Side B has majority when it can communicate with more than half. Each router decides for itself. [cite:1]

Three caps, three pages

The design guide says each Finesse server can support the CTI maximum of 2,000 users, and the total across the two servers in that cluster cannot exceed 2,000. The same chapter names 2000 Agent, 4000 Agent, and 12,000 Agent Reference Designs in a QoS paragraph. A January 2025 Webex CCE what’s-new line says 48,000 concurrent agents and 300 calls per second on a single tenant. Do not add them. [cite:1] [cite:2]

Separate path between Central Controllers and PGs. Also the path that lets fault tolerance tell a dead component from a dead network. [cite:1]

06 · Config

Design rules you can check on a drawing

  1. Draw Side A and Side B as a redundant pair. Do not label them active/active load-balance for the Router. [cite:1]
  2. Draw two physical networks. Put MDS and sync on the private network. Put Central Controller to PG traffic on the public network. [cite:1]
  3. Keep all private traffic for a component on the same link. Do not split low-priority and high-priority private traffic. [cite:1]
  4. Require QoS on private networks. On public links, read the QoS note for the 2000 Agent and 4000 Agent Reference Designs, and the delay warning for the 12,000 Agent Reference Design. [cite:1]
  5. Prefer redundant public connections on different carriers. [cite:1]
  6. Keep devices, call processing, and CTI Manager off the Unified CM publisher where you can. [cite:1]
  7. Size one Finesse cluster to the 2,000-user total. If the paperwork says 48,000 agents, cite the January 2025 Webex CCE sentence and mark it re-check. Do not replace the Finesse line with it. [cite:1] [cite:2]

09 · Self-question ladder

Twelve rungs

L0What are Side A and Side B for?

Redundancy. Not load-balancing. Either side can run the full load, and both process every call. [cite:1]

L1What breaks if the private and public networks share one failure domain?

The design requires two independent physical networks so a single failure does not look like both a dead component and a dead path. A simultaneous failure of both is called catastrophic. [cite:1]

L1Why is Side B’s majority test stricter?

Side A needs at least half of its enabled PGs. Side B needs more than half. [cite:1]

L2What moves on the private network?

Synchronized data, control messages, MDS client communication, and the state transfer used to recover from isolation. [cite:1]

L2What does isolated-enabled mean?

The router has device majority and continues handling traffic. Isolated-disabled means it stops. [cite:1]

L2How long can the private network stay down before logger resync is manual?

14 days, the retention of Config_Message_Log. After that, use Unified ICMDBA. [cite:1]

L3How do you prove an agent sign-out was the split-registration case?

Desktop on one side, phone on the other, public network failed, phone did not rehome, PG could not see the phone. [cite:1]

L3A call is already with an agent when the router peer fails. What does the guide say happens to that call?

A router failure does not affect in-progress calls that have already reached a VRU or an agent. [cite:1]

L3Why can public QoS be a bad idea on a 12,000 Agent Reference Design?

The chapter says QoS on those public links can delay detection of server failures. It allows public QoS in the 2000 and 4000 Agent Reference Designs. [cite:1]

L4How is CUIC HA different from Router HA?

CUIC uses a publisher and up to 7 subscribers and spreads processing around failed nodes. The Router pair does not load-balance. [cite:1]

L4Where does 48,000 come from?

The January 2025 Webex CCE what’s-new entry: 48,000 concurrent agents and 300 calls per second on a single tenant. It is not the Finesse 2,000 line. [cite:2] re-check

L5What constraint stops you from treating both isolated-enabled routers as a permanent design?

The guide calls a dual-network failure catastrophic. If both sides are isolated-enabled, Side B restarts when connectivity returns so it can re-establish communication with its peer. [cite:1]

13 · Interview

Oral answers

30 seconds. Unified CCE runs Side A and Side B for redundancy. Both sides process every call. Either side can carry the full load. I do not load-balance the Router.

2 minutes. Two physical networks. Private carries sync and MDS and must stay on one link per component, with QoS. Public carries Central Controller to PG traffic. If the private network fails, Side A stays up when it sees at least half its enabled PGs. Side B stays up only when it sees more than half. The loser goes isolated-disabled and its logger stops. If the private network returns inside 14 days, logger resync is automatic. A call already at an agent is not dropped just because the router peer failed. If the phone and the desktop are on opposite sides and the public network fails, the agent is signed out.

30 seconds, the caps. Two thousand is the Finesse total on one Agent PG. Forty-eight thousand is a January 2025 Webex CCE sentence, with 300 calls per second. I do not add them.

2 minutes, the other clusters. CUIC is a publisher and up to seven subscribers, and it spreads work around a dead node. Cloud Connect digital routing is active/standby with no dedicated private network. Cisco IdS is its own publisher and subscriber pair. The Unified CM publisher should not run devices, call processing, or CTI Manager if I can avoid it. The design guide I am quoting was updated March 15, 2025, so these rows stay re-check.

What you will not say. You will not treat a 12,000 Agent Reference Design QoS warning as the Webex CCE tenant maximum.
