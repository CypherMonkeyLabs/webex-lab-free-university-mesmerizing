00 · Header

T5 · Dedicated Instance

DI Migration Path

The Dedicated Instance move is seven gates, not a weekend copy. The Control Hub assistant assesses an on-premises Unified CM. It does not migrate the cluster. A certified provider tool does that work. Cutover in the assistant is capped at ten hours.

Room T5-R06 Version v0.1 last-verified: TODO Difficulty L3 Est. time 90–110 min Prereq T5-R02 Reading 17 min

Key takeaways

  • Seven gates: Project Initiation, Discovery and Assessment, Planning, Implementation, Freeze, Go Live, Transfer to Day 2. [cite:1]
  • Production impact is none, then minimum, then limited to operations, then direct at Go Live. [cite:1]
  • The pre-migration assistant does not perform the migration. [cite:2]
  • Freeze is a recommended 2–3 weeks. MACD during freeze is done on both systems. [cite:1]
  • The assistant’s cutover window should not exceed ten hours. Rollback mirrors the cutover. [cite:2] [cite:1]

01 · Executive summary

Five lines, then why it matters

  • The practice article says roughly 95 percent of engineering effort is preparation and 5 percent is the change. That sentence is the article’s framing, not a sizing formula. [cite:1]
  • The assistant tile is visible only when Setup Assist is enabled along with Dedicated Instance. Prerequisites are an active Dedicated Instance subscription, Cloud-Connected UC, and deployment insights. [cite:2]
  • Source readiness sheets cover assessment actions, phone and gateway upgrades, credential policy, and application users. [cite:2]
  • Go-live changes Option 150, resets phones, checks registration on Dedicated Instance, then bulk-updates partitions, home cluster, and advertisements. [cite:1]
  • The same framework names source platforms that include third-party PBX. It does not print an object crosswalk. That gap is T6-R05. [cite:1]
Why it matters. People fail this move by treating the assistant as the migrator, by changing only one system during freeze, or by planning a cutover longer than ten hours in the scheduler.

03 · Core concepts

Gates, then the tool that only assesses

Seven gates

Project Initiation, Discovery and Assessment, Planning, Implementation, Freeze, Go Live, and Transfer to Day 2. Each phase has entry and exit criteria in the practice article. [cite:1]

Impact table

No impact: initiation, discovery, planning. Minimum: implementation. Limited to operations processes: freeze. Direct: go live. [cite:1]

The assistant is not the migrator

It gathers source data, checks prerequisites, and compares on-premises Unified CM with Dedicated Instance. Customers work with a partner who uses a Certified Migration Provider tool to complete the migration. The tile shows only if Setup Assist is enabled along with Dedicated Instance. [cite:2]

Two clocks

The practice article recommends 2–3 weeks of freeze. The assistant says the cutover window should not exceed ten hours. Those are different intervals. Do not call the freeze a ten-hour event. [cite:1] [cite:2]

06 · Config

Scheduler clicks, then the cutover list

  1. Sign in to Control Hub. Open Services → Updates and Migration. Get Started on Pre-Migration Assistant for Dedicated Instance. [cite:2]
  2. Confirm the subscription, Cloud-Connected UC, and deployment insights. Select the prerequisites checkbox. Click Ready to migrate. [cite:2]
  3. After Setup Assist approval, download the source readiness report and approve it. Open Configuration, agree, and submit trunk purpose plus the peering choice. [cite:2]
  4. Add a schedule. Pick destination region and source cluster. Enter freeze start and end. Enter cutover start and end. Keep the cutover at or under ten hours. [cite:2]
  5. During freeze, move Unified CM with BAT, Unity with Cobras if you follow the recommendation, and CER manually or in bulk. Apply MACD on both systems. [cite:1]
  6. On go-live, open the proactive TAC ticket, change Option 150, reset, count registrations, then bulk-update partitions and home cluster. [cite:1]
  7. Run intra-site, inter-site, PSTN, MRA, 911, and voicemail tests. If you miss the window, roll back by reversing the same steps. [cite:1]
  8. When the assistant status is complete, open the DI-readiness, post-migration, and post-registration reports. [cite:2]

13 · Interview

Oral answers

30 seconds. Dedicated Instance migration is seven gates. Most of them do not touch production. Go-live does. The Control Hub assistant checks an on-premises Unified CM and schedules the window. A certified provider tool performs the migration.

2 minutes. Freeze is the recommended two to three weeks where data moves and you test failover. Changes during freeze hit both systems. Unified CM uses BAT. The article recommends Cobras for Unity and manual or bulk for Emergency Responder. Go-live opens a TAC ticket, changes Option 150, resets phones, and uses registration on Dedicated Instance as the progress count. Then you fix partitions, home cluster, gateways, and SRST. Tests include intra-site, inter-site, PSTN, MRA, 911, and voicemail. Rollback repeats those steps backwards before the window ends.

30 seconds, the two clocks. Do not call freeze a ten-hour change. Ten hours is the assistant’s cap on the cutover window. Freeze is the longer data-move phase.

2 minutes, scope. The practice article says the method has been used from a single seat to estates it describes as exceeding 100,000 seats, and from Unified CM, HCS, BroadWorks, BroadCloud, Spark Calling, and third-party PBX. That sentence is not a per-platform runbook. The assistant’s own steps are Unified CM to Dedicated Instance. Day 2 points at Tier 1, service requests, and the RACI.

What you will not say. You will not say the assistant moves the phones. You will not describe Yarnlab beyond the article’s example phrase. You will not add a recorder step these pages do not print.
