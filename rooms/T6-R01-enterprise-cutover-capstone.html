00 · Header

2,000-seat cutover

T6-R01. A Canon planning room for a scenario: 2,000 seats on CUCM and UCCE, moving toward Webex Calling and Webex Contact Center. The seat count is the exercise, not a Cisco limit.

Reading 11 minDraftStudy notes

Key takeaways

  • Size trunks from concurrent calls. 2,000 seats is not 2,000 calls. [cite:2]
  • Do not import ICM scripts. The crosswalk stays marked in T6-R04. [cite:4]
  • Premises users cannot use cloud PSTN. [cite:3]
  • WebRTC agents do not go live before 933. [cite:7]

03 · Core

What you may claim

The calling half starts from the Unified CM migration introduction. It is not a CSS conversion table. [cite:1]

As of 2026-10-14, t9xctu Table 5 maps concurrent calls to a trunk preference: up to 250 registration-based OTT, about 250–2000 certificate-based OTT, about 2000–6500 certificate-based interconnect. A 2,000-seat office can sit in any row depending on busy-hour calls. [cite:2]

n0xb944 says calls originating from premises users cannot access cloud PSTN. Mixed sites need a premises path for the users who have not moved. [cite:3]

The contact-center half is T6-R04. Three tools exist, and none of them imports an ICM script. The CCX discovery tool is not pointed at a UCCE logger. Skill groups, peripherals, CUIC, Finesse, and UCCE dialed numbers stay marked there. [cite:4]

The objects you can build from the architecture article are the entry point, the flow, the queue, and the team. [cite:5]

04 · Ecosystem

Ecosystem and sister technologies

Scenario size
2,000 seats is the design exercise in this room. It is not a Cisco limit and it is not a concurrent-call count.
Canon planning
The phase list and the cutover runbook below are a Canon method. Cisco has not published a 2,000-seat CUCM plus UCCE runbook in the articles this room cites.
PPDIO
The calling migration introduction is the door for Unified CM to Webex Calling. The contact-center cutover is not that article. [cite:1]
Concurrent calls
t9xctu Table 5, as of 2026-10-14: up to 250 concurrent prefers registration OTT; about 250–2000 prefers certificate OTT; about 2000–6500 prefers certificate interconnect. Size trunks from concurrent calls. [cite:2]
Premises PSTN limit
Calls that originate from premises users cannot use cloud PSTN. [cite:3]
CSS versus patterns
CUCM closest-match is the CallManager System Guide rule: every partition, closest match, order only as a tie-break. That is not the Webex wildcard engine. Field equivalence stays marked in T6-R02 and T2-R03. [cite:10]
No ICM import
None of the three published tools imports an ICM script into Flow Designer. Those rows stay marked in T6-R04. [cite:4]
CCX jar is not UCCE

Entry point
The multi-tenant front door: entry point, flow, queue, team. [cite:5]
Pilot
The 1.0 article says test a few users before you move everyone. That article is inside WxCC 1.0, not UCCE. The Canon method copies the caution, not the product. [cite:6]
933 before agents
WebRTC agents need RedSky tested before they take live calls. [cite:7]
Recording choice
Quote both nhvl4hw defaults. Recording also disables Calling E2EE. [cite:8] [cite:9]
Analyzer versus CUIC
Canon planning: keep CUIC until a person compares one report. nb2ve0e cleanup makes legacy Analyzer data available. That article does not mention CUIC. The CUIC row stays marked in T6-R04. [cite:6]
Dual desktop
Finesse and Agent Desktop on the same UCCE call stays marked in T6-R04. This runbook does not schedule that coexistence.
Number move
Canon planning: move one number only after the new flow answers. Do not move numbers with the CCX workbook. That workbook is a CCX extract, cited from T6-R04.
Rollback
Leave the old route in place until the new path has answered a test call. Canon planning, not a Cisco command.

05 · Flow

Phases

  1. Inventory, Canon planning. List sites, CSS and partitions, route patterns, devices, and busy-hour concurrent calls. List UCCE dialed numbers, call types, skill groups, and scripts as names you will rebuild, not as objects a tool will convert. [cite:1] [cite:4]
  2. Calling design. Follow the Unified CM migration introduction for users you intend to move. Keep CUCM closest-match out of the Webex pattern engine. [cite:1]
  3. Trunk and PSTN. Choose registration or certificate from concurrent calls, not from 2,000 seats. Premises users do not get cloud PSTN. [cite:2] [cite:3]
  4. Security choices before the pilot. Quote both recording defaults. If a call must be recorded, Calling E2EE is off. Build RedSky and pass 933 before any WebRTC agent is in the pilot. [cite:7] [cite:8] [cite:9]
  5. Contact center beside the old estate. Create entry points, flows, queues, and teams. Do not run the CCX jar. Do not rename ICM nodes. [cite:4] [cite:5]
  6. Pilot. A few agents, one flow, lab numbers. The caution to test a few users first is the WxCC 1.0 article, not a claim that UCCE uses that portal. [cite:6]
  7. One number. Canon planning. Cut a single dialed number only after the new flow answers. Leave the old route until that call is logged.
  8. Reports. Canon planning. Leave CUIC up. Compare a named report in Analyzer by hand. T3-R07 has the clocks. nb2ve0e does not convert CUIC. [cite:6]
Canon planning

06 · Config

Cutover runbook

  1. Freeze a window. Write the one number, the entry point, and the rollback route on one page.
  2. Confirm RedSky from nvfbjts: 933 has been placed, Emergency call routing is the mode you intend, and each pilot agent’s identification type is Device User Id equal to the email. Header September 08, 2024. re-check [cite:7] mwjlgk, header September 03, 2025, is the agent install. It confirms https://wxc.e911cloud.com and a verification email. It does not replace those admin steps. [cite:11]
  3. Confirm the flow is published and a lab call has reached an agent.
  4. Move that one number. Place one test call. Save the result.
  5. If the call fails, send it back to the route you did not delete. Do not debug by moving the rest of the range.
  6. If the call succeeds, leave CUIC and the old scripts in place. Expand only after a written comparison.

This runbook is Canon planning. It is not nbedetf, not the CCX workbook, and not the WxCC 1.0 portal move.
