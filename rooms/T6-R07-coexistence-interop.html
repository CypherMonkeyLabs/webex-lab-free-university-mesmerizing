T6 · Migrations

Coexistence and interop

Phased Unified CM to Webex Calling, and multi-tenant calling beside Dedicated Instance. This room is the dial plan that keeps both sides talking while users still live on both. Retrieved 2026-10-14.

Room T6-R07 Version v0.1 last-verified: TODO Difficulty L3 Est. time 90–120 min Prereq T6-R02, T5-R02 Reading 16 min

Key takeaways

  • A phased move splits users across Unified CM and Webex Calling. Each batch needs dial-plan updates on both platforms and on the Local Gateway. [cite:1]
  • Put Webex Calling +E.164 patterns in their own partition. The inbound calling search space on the Local Gateway trunk must not include that partition, or the design loops. [cite:2]
  • A Local Gateway does not split a shared feature. Call queues and the users who depend on them move in the same batch. [cite:3]
  • Dedicated Instance interop trunks are certificate-based and created by Cisco. The base-configuration article says not to modify or delete them. A main number and a PSTN connection are required on the interop location. [cite:4] [cite:5]
  • Calls that originate from premises users cannot use cloud PSTN. Cloud PSTN is for Webex Calling users. [cite:6]

01 · Executive summary

Both sides stay routable

  • A phased move splits users across Unified CM and Webex Calling. Each batch needs dial-plan updates on both platforms and on the Local Gateway. [cite:1]
  • Put Webex Calling +E.164 patterns in their own partition. The inbound calling search space on the Local Gateway trunk must not include that partition, or the design loops. [cite:2]
  • A Local Gateway does not split a shared feature. Call queues and the users who depend on them move in the same batch. [cite:3]
  • Dedicated Instance interop trunks are certificate-based and created by Cisco. The base-configuration article says not to modify or delete them. A main number and a PSTN connection are required on the interop location. [cite:4] [cite:5]
  • Calls that originate from premises users cannot use cloud PSTN. Cloud PSTN is for Webex Calling users. [cite:6]
Why it matters. The failure mode is a loop, a split queue, or a premises user pointed at cloud PSTN. Those three are written down. A parity chart is not.

03 · Core concepts

Keep the batch, the partition, and the PSTN in their lanes

Two call controls at once

nw9po3o describes a single-step move, where the soft client and the calling service change together, and a dual-step move, where users go from Jabber to the Webex App first and stay on Unified CM until a later calling cut. While groups move, enterprise users are split across the two platforms. [cite:1]

The loop rule

nqojzwt says create a dedicated Webex Calling partition, put +E.164 route patterns for Webex Calling destinations in it, and add that partition only to calling search spaces that must reach Webex Calling. To avoid call loops, the inbound calling search space on the trunk from the Local Gateway should not have access to the Webex Calling partition. [cite:2]

Shared features do not straddle the trunk

q0pgpb says that even with Local Gateway interworking you cannot split shared services or features across that connection. The example it names is call queues. Dependent users migrate in the same batch. Cisco recommends migrating a physical site or a department at the same time when you can. [cite:3]

Dedicated Instance is a different interop

ny65x1bb says calling features are not fully harmonized between multi-tenant and Dedicated Instance. Keep users who need call pickup, hunt groups, or manager/secretary on one call control. Keep contiguous numbers on the same call control. [cite:5]

04 · Ecosystem & sister technologies

Glossary, map, sisters, edges

Glossary

Phased migration
Users move in groups. Until the last group moves, some users are on Unified CM and some are on Webex Calling. Each group requires dial-plan updates on Unified CM, Webex Calling, and the Local Gateway. [cite:1]
Single-step migration
nw9po3o: the user moves from Jabber to the Webex App at the same time the calling service moves from Unified CM to Webex Calling. [cite:1]
Dual-step migration
Step 1 moves the soft client to the Webex App and leaves calling on Unified CM. Step 2 moves calling. nw9po3o recommends this for larger customers who want those changes separated. [cite:1]
Webex Calling partition
A Unified CM partition that holds +E.164 route patterns for destinations that now live on Webex Calling. The Local Gateway trunk’s inbound calling search space must not contain it. [cite:2]
Fixed extension length
nqojzwt: every extension in a Webex Calling deployment has the same length. Internal extension length in Control Hub can be any value between two and ten. [cite:2]
Abbreviated inter-site dialing
Extension dialing between locations works only when the dialed extension is unique. Overlaps need a steering digit and a site code. [cite:2]
Steering digit
The first digit of the routing prefix for abbreviated enterprise inter-location dialing. nqojzwt says to avoid overlap with the first digit of any location and with location outbound dial digits. [cite:2]
Local Gateway
q0pgpb: one or more Local Gateways are required if the organization keeps hybrid dual call control, so Webex Calling and Unified CM endpoints can call each other and so on-premises PSTN can be used. [cite:3]
Shared feature
A feature whose members must stay together. q0pgpb names call queues. Hunt groups are in the same dependency list in that section. [cite:3]
Calls to On-Premises Extensions
A per-location Control Hub setting. Unknown extensions of calling-number length 2–10 digits route to a PBX on an existing trunk or route group. [cite:6]
Cloud PSTN boundary
n0xb944: Cloud PSTN, Cisco PSTN or Cloud Connected PSTN, provides PSTN access for Webex Calling users. Calls originating from premises users cannot access cloud PSTN. [cite:6]
Route group
One to ten trunks. Trunks at the same priority share calls at random. If the higher-priority trunks are unavailable, the call uses a lower priority. [cite:6]
WXC-DI trunk
2vpf1: one SIP trunk to each Dedicated Instance data center in a region, for basic interop. Default trunks created by Cisco. The article says they should not be modified or deleted. [cite:4]
Interop location
2vpf1: a location is mandatory to activate the interop SIP trunk. A PSTN connection and a main number are required. Without the main number, users cannot make or receive calls through the route group for that location. Premise-based PSTN is allowed when you are not using CCPP. [cite:4]
Certificate interop
ofrt6u: the preconfigured SIP connectivity between Dedicated Instance and multi-tenant is certificate-based and rides the Cisco Webex backbone. Those trunks have to be activated before calls work. [cite:7]
Contiguous numbers
ny65x1bb recommends keeping contiguous phone numbers on the same call control when you split users between multi-tenant and Dedicated Instance. [cite:5]

06 · Config

Paths

  1. Read nw9po3o and choose single-step or dual-step before you touch a phone. Dual-step keeps calling on Unified CM while the soft client moves. [cite:1]
  2. On Unified CM, add the Webex Calling partition and the +E.164 route patterns for ranges that have already moved. Add the partition to the calling search spaces that need it. [cite:2]
  3. On the SIP trunk from the Local Gateway, confirm the inbound calling search space cannot see that partition. [cite:2]
  4. In Control Hub calling service settings, set internal extension length (2–10), and set routing-prefix length and steering digit only if you need an enterprise numbering plan. [cite:2]
  5. For each mixed location, enable Calls to On-Premises Extensions toward the trunk or route group that still reaches the PBX. [cite:6]
  6. Build route groups with at least one trunk and at most ten. Same priority load-balances at random. A lower priority is the failure path. [cite:6]
  7. If Dedicated Instance is in the estate, leave WXC-DI trunks and route groups in place, set the interop location’s PSTN connection and main number, and activate the certificate trunk. Point custom dial plans at that route group. [cite:4] [cite:7]
  8. Move one site or one dependency batch. q0pgpb says test a subset of that group, including any call queue or hunt group that moved with them, before the next batch. The test script is T6-R08. [cite:3]

09 · Self-question ladder

Twelve rungs

L1What does a phased migration do to the user population?

It splits users across Unified CM and Webex Calling until the move finishes. [cite:1]

L1What is the difference between single-step and dual-step?

Single-step moves the soft client and the calling service together. Dual-step moves the soft client first. [cite:1]

L2Why does the Webex Calling partition exist on Unified CM?

So +E.164 destinations that live on Webex Calling have route patterns, and so you can build a class of service that reaches them. [cite:2]

L2Which calling search space must not see that partition?

The inbound calling search space on the trunk from the Local Gateway. That is the loop avoidance rule. [cite:2]

L2How long is a Webex Calling extension?

One global length. Control Hub allows any value between two and ten. [cite:2]

L3When does abbreviated inter-site extension dialing work?

Only when the dialed extension is unique. Overlaps need a steering digit and site code. [cite:2]

L3Can a call queue have members on both platforms?

q0pgpb says you cannot split shared services across the Local Gateway connection. Move the dependent users together. [cite:3]

L3Who can use cloud PSTN?

Webex Calling users. Calls originating from premises users cannot access cloud PSTN. [cite:6]

L4How does a route group choose a trunk?

Same priority is random load balancing. If those trunks are unavailable, a lower priority is tried. Maximum 10 trunks. [cite:6]

L4What must the Dedicated Instance interop location have?

A PSTN connection and a main number. Otherwise users cannot place or receive calls through that location’s route group. [cite:4]

L5What does ofrt6u change for older registration-based interop?

Relink the route list and dial plan to the route group on the certificate-based trunk. The article’s example moves xWxC_ _RL to xWxC_MT_ _RG. [cite:7]

L5Why keep contiguous numbers on one call control?

ny65x1bb says that simplifies dial plan and routing when you split multi-tenant and Dedicated Instance. Group features are not fully harmonized. [cite:5]

11 · Quiz

Twelve questions

Q1MCQ

During a phased move, where do users live?

Answer

On both Unified CM and Webex Calling until the groups finish moving. Each group updates dial plans on both platforms and the Local Gateway. [cite:1]

Q2MCQ

Single-step means:

Answer

Soft client and calling service move at the same time. [cite:1]

Q3MCQ

The Webex Calling partition is for:

Answer

+E.164 route patterns toward destinations that live on Webex Calling, and a class of service that can reach them. [cite:2]

Q4Scenario

You add the Webex Calling partition to the Local Gateway trunk’s inbound CSS. What does nqojzwt say you risk?

Answer

Call loops. That inbound CSS should not have access to the Webex Calling partition. [cite:2]

Q5MCQ

Webex Calling extension length is:

Answer

A fixed global setting. Control Hub allows any value between two and ten. [cite:2]

Q6Scenario

NYC and RTP both use extension 2001. What does abbreviated inter-site dialing need?

Answer

An enterprise numbering plan. nqojzwt’s example uses a steering digit, a site code, and the extension, because the bare extension is not unique. [cite:2]

Q7MCQ

A call queue with members on both sides of the Local Gateway:

Answer

q0pgpb says shared services cannot be split across that connection. Move the dependent users in one batch. [cite:3]

Q8MCQ

Cloud PSTN serves:

Answer

Webex Calling users. Premises-originated calls cannot access it. [cite:6]

Q9MCQ

A route group may contain:

Answer

At least one trunk and at most ten. Same priority is random. Lower priority is failover. [cite:6]

Q10Scenario

Dedicated Instance users cannot call multi-tenant. The WXC-DI location has no main number. What does 2vpf1 say?

Answer

Users cannot make or receive calls through the route group for that location until the main number is configured. A PSTN connection is also required. [cite:4]

Q11Draw

Write the ofrt6u routing change in one line.

Answer

Point the route pattern that used the registration-based route list at the certificate-based route group. The article’s example is xWxC_ _RL to xWxC_MT_ _RG. [cite:7]

Q12Scenario

A partner deletes a WXC-DI trunk to “clean up.” What does 2vpf1 say?

Answer

Those default trunks should not be modified or deleted. [cite:4]
