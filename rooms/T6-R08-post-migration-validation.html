00 · Header

T6 · Migration

Post-migration Validation

After a group moves, you test a subset and you test the queues and hunts that moved with them. After everyone has moved, Unified CM’s remaining job can be transit between the PSTN gateways and Webex Calling. Cleanup then removes the discovery records, the DHCP options, and the virtual machines. Dedicated Instance post-migration reports live in T5-R06.

Room T6-R08 Version v0.1 last-verified: TODO Difficulty L3 Est. time 80–100 min Prereq T6-R07 Reading 16 min

Key takeaways

  • The pilot uses the same Cisco and third-party tools as the full move, and it takes voicemail, auto attendants, queues, and hunts with the users. [cite:1]
  • Number checks confirm extension, external number, on-net routing, PSTN routing, and overlaps. [cite:1]
  • Queue acceptance language in that article is “round robin, longest idle, or simultaneous ring.” That is a Calling test phrase, not the Webex Contact Center queue catalog. [cite:1]
  • To leave premises PSTN, port every number on the Unified CM trunk to the Cloud Connect partner at the same time, then point every location at that provider. [cite:2]
  • Remove cisco_uds._tcp and cup_login._tcp from on-premises DNS, collab_edge._tls from public DNS, and DHCP options 66 and 150. [cite:2]

01 · Executive summary

Five lines, then why it matters

  • On-net tests cover transfer, hold, forwarding, and conferencing. PSTN tests cover inbound to users, queues, hunts, and auto attendants, plus outbound caller ID. [cite:1]
  • Hunt tests check the configured algorithm, overflow, forwarding, no-answer, and that membership and routing match what was on Unified CM. The article states that as the test goal. [cite:1]
  • If hybrid trunking was used from the start, the guide says there is no extra PSTN migration step after the users move, beyond decommissioning Unified CM and the Local Gateways. [cite:2]
  • Put migrated directory numbers in a hidden partition so calling search spaces prefer the cloud path. [cite:2]
  • Analytics cover media quality, call history, call queue, hunt group, and auto attendant. Troubleshooting can integrate ThousandEyes and Meraki. The detailed guide is “Troubleshoot Webex Calling calls in Control Hub.” [cite:2]
Why it matters. Validation fails when option 150 is still handing phones a Unified CM TFTP address, or when a queue test borrows a Webex Contact Center pattern name the Calling article did not use.

PSTNInbound to users, queues, hunts, or auto attendants. Outbound with the correct caller name and number.[cite:1]

06 · Config

Paths you can cite

  1. After each batch, compare extensions and DIDs with the Unified CM directory. Place on-net and PSTN calls. Check overlaps. [cite:1]
  2. If a queue moved, confirm distribution against the logic you configured. The article’s examples are round robin, longest idle, and simultaneous ring. [cite:1]
  3. For a hunt, confirm the algorithm, overflow, forwarding, no-answer, and that membership matches Unified CM. [cite:1]
  4. Before a Cloud Connect cutover, provision a test location, point it at the partner, call through it, and deprovision it. [cite:2]
  5. Port every number on the Unified CM PSTN trunk together. On the day, set each location’s PSTN and verify inbound and outbound. [cite:2]
  6. Remove the SRVs and DHCP options, hide the migrated DNs, update Horizon Mobility when the building network changes, and delete the virtual machines the guide names. [cite:2]
  7. Open Control Hub analytics for media quality, call history, queues, hunts, and auto attendants. For a failed call, follow Troubleshoot Webex Calling calls in Control Hub, article frj1efb. [cite:2]
Warn. Do not power off Unified CM while it is still the transit between PSTN gateways and Webex Calling, unless you have already moved PSTN or you started on hybrid trunking and the guide’s “no additional PSTN step” sentence applies. [cite:2]

13 · Interview

Oral answers

30 seconds. Validate a representative pilot with the same tools you will use later, and move voicemail, attendants, queues, and hunts with those people. After each group, test a subset. The written acceptance list is a sample, not a complete script.

2 minutes. Check extensions and DIDs, on-net and PSTN, and overlaps. On-net means transfer, hold, forwarding, and conferencing. PSTN means the call lands on the right user or queue and the far end sees the right caller ID. For a Calling queue, the article’s examples are round robin, longest idle, and simultaneous ring. That sentence is not the Webex Contact Center pattern list. For a hunt, match the algorithm, overflow, and the membership you had on Unified CM.

30 seconds, transit. When everyone is on Webex Calling and PSTN is still local, Unified CM only forwards calls between the gateways and Webex Calling. Do not shut it off in that state.

2 minutes, cleanup. Test Cloud Connect on a throwaway location, then deprovision it. Port every number on the Unified CM trunk together and flip every location the same day. If you started with hybrid trunking, the guide says you skip that PSTN migration and only decommission Unified CM and the gateways. Then remove the UDS, login, and collab-edge SRVs, DHCP options 66 and 150, and the dial-peers. Hide the old directory numbers. Delete Unified CM, Expressway, and Unity Connection. Do not promise that old voicemail messages came along. Update Horizon Mobility when the switches or the floor plan change.

What you will not say. You will not recite Dedicated Instance post-migration report names in this room. You will not call the acceptance section complete. You will not invent steps from the troubleshooting article; you will name frj1efb and stop.
