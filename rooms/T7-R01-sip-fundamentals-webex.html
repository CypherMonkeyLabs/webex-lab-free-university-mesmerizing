T7 · SIP, routing, and queues

SIP Fundamentals for Webex

The Local Gateway speaks SIP to Webex Calling over TLS, and media is SRTP. This room is the dial-peer and the debug, not another PSTN overview. Sample passwords from the configuration guide are not here.

Room T7-R01 Version v0.1 last-verified: TODO Difficulty L3 Est. time 100–120 min Prereq T2-R02 Reading 17 min

Key takeaways

  • The trunk to Webex Calling is SIP over TLS. Media is SRTP. Commercial gateways offer AES_CM_128_HMAC_SHA1_80. [cite:1]
  • Registration trunks are CUBE only and stop at 250 calls. Certificate trunks go past 250 and need OPTIONS from the gateway FQDN. [cite:2]
  • The Webex dial-peer matches inbound calls with incoming uri request. BAD.BAD is a dummy destination-pattern, and max-conn 250 belongs on a registration trunk. [cite:1]
  • Inbound SIP matching checks URI headers before called number. Outbound hunt 0 prefers the longest match, then the lower preference number. [cite:3]

03 · Core concepts

Match rules that change the peer

One criterion is enough

An inbound dial-peer does not need every command to match. IOS XE searches all peers for the first criterion, and only then moves on. The match is on the whole message, not digit by digit. [cite:3]

Two ciphers, two clouds

SHA1_80 is the commercial block. AEAD_AES_256_GCM is the Government block, and the article says the SHA1 step is not applicable there. [cite:1]

Debugs are not the first page

jr1i3r spends its troubleshooting section on diagnostic signatures and tells you to install DS 64224 so a CPU spike uninstalls them. 211306 still names the show and debug commands that explain hunt. Use the commands with the safety the Local Gateway article wrote down. [cite:1] [cite:3]

No sample secrets

jr1i3r shows a registrar, a username, and a password in a tenant example. Those values are the guide’s illustration. Read the trunk in Control Hub and type those values on the gateway. Sample passwords in a tenant example are not your trunk, and they change per organization. [cite:1]

04 · Ecosystem & sister technologies

Glossary, map, sisters, edges

Glossary

Local Gateway
The customer SBC that trunks to Webex Calling. SIP TLS secures the signaling. SRTP secures the media. [cite:1]
Registration trunk
Digest authentication, CUBE only, up to 250 concurrent calls. The sample dial-peer sets max-conn 250 and the article says that is the maximum for a registration trunk. [cite:1] [cite:2]
Certificate trunk
Certificate authentication and FQDN checks. Concurrent calls above 250. Every SIP transaction the gateway starts, including OPTIONS, needs a Contact header with the gateway FQDN or Control Hub will not show the gateway online. [cite:2]
Webex for Government
Certificate-based only, and CUBE is the only SBC the get-started article names for it. The commercial SHA1_80 step is marked not applicable. GCM is mandatory. [cite:1] [cite:2]
voice class tenant
Groups the trunk’s registrar or sip-server, transport, and SRTP crypto so the dial-peer can inherit them. [cite:1]
SRTP SHA1_80
Commercial Webex Calling: the article’s crypto class offers AES_CM_128_HMAC_SHA1_80 and says Webex Calling only supports SHA1_80. [cite:1]
SRTP GCM
Webex for Government: AEAD_AES_256_GCM is mandatory. Do not paste the commercial cipher onto a Government gateway. [cite:1]
incoming uri request
Matches the inbound INVITE to the Webex dial-peer. The article’s uri class looks for the trunk’s dtg= value from Control Hub. [cite:1]
BAD.BAD
A dummy destination-pattern on the Webex dial-peer. The article says a dummy is required when outbound calls are routed with an inbound dial-peer group. It is not a number your users dial. [cite:1]
session target sip-server
Sends the outbound leg to the SIP server inherited from the tenant. [cite:1]
OPTIONS keepalive
A voice class sip-options-keepalive profile. Certificate trunks depend on OPTIONS for the Control Hub online state. The article’s sample uses transport tcp tls. [cite:1] [cite:2]
Inbound SIP order
IOS XE checks URI via, then URI request, then URI to, then URI from, then called number, then calling number, then destination-pattern against the ANI. The first criterion that matches wins. It is not digit-by-digit. [cite:3]
dial-peer hunt 0
The default hunt: longest match, then explicit preference, then random. Preference 0 is better than preference 1. [cite:3]
huntstop
Stops the gateway from trying the next outbound dial-peer after a failure. [cite:3]
show dial-peer voice summary
The IOS routing article prints this command. The summary line includes the hunt scheme. [cite:3]
debug voip ccapi inout
The same article prints this debug when a call fails on the first dial-peer and hunts. It is not the Local Gateway article’s first troubleshooting step. [cite:3] [cite:1]
Diagnostic signature
The Local Gateway article’s troubleshooting method. TAC-authored, signed XML. A high-CPU signature disables debugs. [cite:1]
DS 64224
The article tells you to install this high-CPU signature so that at 75 percent CPU it disables all debugs and uninstalls diagnostic signatures. [cite:1]
Config Validation
A Control Hub check for registration-based Local Gateways only. It validates the Webex-facing dial-peers, tenant, and trustpoint. It does not validate the PSTN dial plan. [cite:4]
ICE-Lite
stun usage ice lite on Webex-facing dial-peers so media can optimize. The article says recording and other cloud media services cannot be optimized. [cite:1]

06 · Config

The lines worth typing, without the sample password

  1. In Control Hub, create the trunk and copy the registrar or sip-server, the OTG/DTG, and the credentials into a private store. Do not copy them from the guide’s example. [cite:1]
  2. Install the Cisco core trust bundle the article names: crypto pki trustpool import clean url https://www.cisco.com/security/pki/trs/ios_core.p7b. [cite:1]
  3. Create the commercial SRTP class, the dtg= URI class, and dial-peer 100 as below. Set max-conn no higher than 250 on a registration trunk. [cite:1]
  4. On a certificate trunk, add the OPTIONS keepalive profile and make sure Contact carries the gateway FQDN. [cite:1] [cite:2]
  5. On Webex for Government, skip the SHA1 class and configure AEAD_AES_256_GCM. Use CUBE and a certificate trunk. [cite:1] [cite:2]
  6. Confirm hunt with show dial-peer voice summary. If a call hunts, debug voip ccapi inout is the command 211306 prints. Install DS 64224 first so 75 percent CPU disables debugs. [cite:3] [cite:1]
  7. Run Config Validation only as a registration-trunk check. Then test the PSTN peer yourself. [cite:4]

09 · Self-question ladder

Twelve rungs

L1What secures the Local Gateway trunk to Webex Calling?

SIP TLS for signaling and SRTP for media. [cite:1]

L1Which cipher does commercial Webex Calling get in the article’s crypto class?

AES_CM_128_HMAC_SHA1_80. The article says Webex Calling only supports SHA1_80. [cite:1]

L2What is different for Webex for Government?

Certificate-based, CUBE only, and GCM (AEAD_AES_256_GCM) instead of the SHA1_80 step. [cite:1] [cite:2]

L2Why is max-conn 250 on the sample Webex dial-peer?

Registration trunks max out at 250 concurrent calls. The article says the configured maximum should be 250. [cite:1]

L2What is BAD.BAD?

A dummy destination-pattern required when an inbound dial-peer group routes the outbound leg. [cite:1]

L3Why does a certificate trunk need OPTIONS?

Control Hub uses those OPTIONS transactions, with the FQDN in Contact, to show the gateway online. [cite:2]

L3What is the inbound SIP match order?

URI via, URI request, URI to, URI from, called number, calling number, then destination-pattern on the ANI. First matching criterion wins. [cite:3]

L3What does dial-peer hunt 0 do?

Longest match, then the lower preference number, then random. [cite:3]

L4Which debug does the routing article name for a hunting failure?

debug voip ccapi inout. show dial-peer voice summary shows the hunt. debug voip uri is also printed for URI matches. [cite:3]

L4What does the Local Gateway article want in place before debugs?

Diagnostic signatures, including DS 64224, which disables debugs at 75 percent CPU. [cite:1]

L5What will Config Validation refuse to judge?

The PSTN and on-prem PBX dial plan. It is registration-based Local Gateway config only. [cite:4]

L5Why is a recorded call a bad ICE example?

The article says media that needs a cloud service such as recording cannot be optimized. [cite:1]

Q5Scenario

An INVITE has a dtg= that matches voice class uri, and also a called number that matches another peer. Which peer wins?

Answer

The URI request match. URI criteria are ahead of called-number. [cite:3]

Q6Scenario

Answer

The longer match, 200. Preference is the tie-break after length. [cite:3]

13 · Interview

Oral answers

30 seconds. Local Gateway is a SIP TLS trunk with SRTP. [cite:1] Registration is CUBE and up to 250 calls, and registration trunks digest-authenticate. [cite:2] Certificate trunks use the getting-started “greater than 250” sentence. Table 5 is not flattened into it. They send OPTIONS with their FQDN or Control Hub marks them down. [cite:2]

2 minutes. Inbound SIP matching is URI via, request, to, from, then called number, then calling number, then destination-pattern on the ANI. [cite:3] The Webex sample peer matches incoming uri request on dtg= and uses BAD.BAD only as a dummy. [cite:1] Outbound, hunt 0 takes the longest pattern and then the lower preference. [cite:3] Read the hunt order in the SBC vendor’s own guide. This room only cites CUCM closest-match and CUBE preference, and those two engines already differ.

30 seconds, ciphers. Commercial is AES_CM_128_HMAC_SHA1_80. Webex for Government is AEAD_AES_256_GCM, certificate, CUBE only. [cite:1] [cite:2]

2 minutes, debugs. show dial-peer voice summary shows the hunt. debug voip ccapi inout shows a failed leg that hunts. debug voip uri is for URI matching. Before those stay enabled, jr1i3r wants DS 64224 so 75 percent CPU shuts debugs off. [cite:1]

What you will not say. You will not recite the sample password, and you will not build a firewall ACL from memory.
