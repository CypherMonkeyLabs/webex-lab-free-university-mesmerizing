T7 · SIP, routing, and queues

SIP trunk design

Certificate and registration trunks, route-group priority, and the FQDN that must sit in the certificate. Retrieved 2026-10-14.

Key takeaways

  • A route group holds at least one trunk and at most ten. Same priority is random load balancing. A lower priority is used when the higher-priority trunks are unavailable. [cite:1]
  • Trunk status is online, offline, impaired, or unknown. The page updates every 3 minutes. Online means every Webex Calling edge proxy reached the Local Gateway. Impaired means at least one proxy did not. [cite:1]
  • Error 6 is an FQDN missing from the certificate CN or SAN. The jwkbt2 example strips :5061 off london.lgw.cisco.com. [cite:1] [cite:2]

01 · Executive summary

Ten trunks, two priorities, one FQDN

  • A route group holds at least one trunk and at most ten. Same priority is random load balancing. A lower priority is used when the higher-priority trunks are unavailable. [cite:1]
  • Trunk status is online, offline, impaired, or unknown. The page updates every 3 minutes. Online means every Webex Calling edge proxy reached the Local Gateway. Impaired means at least one proxy did not. [cite:1]
  • Error 6 is an FQDN missing from the certificate CN or SAN. The jwkbt2 example strips :5061 off london.lgw.cisco.com. [cite:1] [cite:2]
  • t9xctu: wildcard certificates are not supported. Certificates with only Server Authentication EKU are supported. Webex does not require Client Authentication EKU. [cite:3]
  • Each Local Gateway is assigned to two Webex Media PoPs in the region, through DNS SRV, for redundancy. [cite:3]
Why it matters. Impaired is not offline. A wildcard that a CA issued is still not a Webex Calling trunk certificate.

03 · Core concepts

Status words and certificate names

Priority is not weight

n0xb944’s route-group example: trunks 1 and 2 at priority 1 share calls. Trunk 3 at priority 2 is used when 1 and 2 are unreachable. SRV weight and priority are a different sentence, on the DNS records for calls originating from Webex Calling. [cite:1]

Errors 2, 6, 11, and 12

Those four are shown only when all edge proxy nodes have the problem. A single-proxy failure is the impaired state, not that short list. [cite:1]

More than 1000 trunks

If search returns more than 1000 trunks, you cannot sort or search within the results. [cite:1]

Two PoPs

t9xctu says the assignment is geographic. An EU gateway uses two media PoPs in the EU. [cite:3]

04 · Ecosystem & sister technologies

Glossary, map, sisters, edges

Glossary

Trunk
The connection from Webex Calling to a local gateway or other supported device. [cite:1]
Registration trunk
The SBC registers. t9xctu: up to 250 concurrent calls, and the getting-started table limits that model to CUBE. [cite:3]
Certificate trunk
You enter an FQDN. Webex trusts the gateway from that FQDN plus the certificate. Concurrent calls above 250 in the getting-started wording. Table 5 is a separate band table and is not flattened here. [cite:1] [cite:3]
Route group
1 to 10 trunks, possibly from multiple locations. [cite:1]
Priority
Same number means random distribution. Lower priority is the backup. [cite:1]
SRV weight
DNS records for the gateway FQDN. Differing weight and priority change distribution of calls from Webex Calling. Use the same listening port on those records. [cite:1]
FQDN in the certificate
CN or SAN must match the Control Hub FQDN, without the port. [cite:2]
Wildcard
Not supported, in t9xctu. [cite:3]
Server Authentication EKU
Supported alone. Client Authentication EKU is not required by Webex. Some third-party SBCs reject that certificate. [cite:2] [cite:3]
Two media PoPs
Assigned at provisioning, via DNS SRV, inside the region. [cite:3]
OPTIONS
Error 7: OPTIONS sent to the Local Gateway got no response. Error 11: the gateway is not sending OPTIONS toward Webex. [cite:1]
3 minutes
Trunk status updates on that interval. Refresh is still manual if you want the page now. [cite:1]
Impaired versus all-proxy errors
Impaired is one proxy. Errors 2, 6, 11, and 12 appear when every proxy is affected. [cite:1]
Calls to on-premises extensions
Per location. Unknown extensions of 2–10 digits can use a trunk or route group. [cite:1]
Premises PSTN boundary
Calls originating from premises users cannot access cloud PSTN. [cite:1]
DI interop trunk
Separate from a customer Local Gateway. ofrt6u activates the certificate trunk Cisco already created. [cite:4]

06 · Config

Control Hub, then the certificate

  1. Add the trunk before the route group. Path for the route group: Services > PSTN & Routing > Gateway configurations. Cisco Calling Plan customers can add a route group from Services > Calling > Call Routing. [cite:1]
  2. Set priorities. Put backups on a lower priority than the pair that should share load. [cite:1]
  3. For a certificate trunk, put the FQDN in Control Hub and in the certificate CN or SAN. Do not include the port in the certificate name. [cite:2]
  4. Reject wildcard certificates. Confirm Server Authentication EKU. [cite:3]
  5. Read status after 3 minutes. Use Refresh for the latest timestamp. [cite:1]
  6. If Dedicated Instance interop is also in the design, activate ofrt6u’s certificate trunk. Do not edit the WXC-DI objects. [cite:4]

13 · Interview

Oral answers

30 seconds. A route group has up to ten trunks. Equal priority load-balances at random. A lower priority is the failure path. Status is online, offline, impaired, or unknown, every 3 minutes. [cite:1]

2 minutes. The certificate FQDN matches Control Hub without the port. Wildcards are out. Server Authentication EKU is enough for Webex, and some SBCs still want client EKU. [cite:2] [cite:3] Two media PoPs come from SRV inside the region. [cite:3] Errors 2, 6, 11, and 12 mean every proxy is in trouble. [cite:1]

30 seconds, OPTIONS. Error 7 is no response to OPTIONS. Error 11 is the gateway not sending them. [cite:1]

2 minutes, what I leave alone. I do not edit Dedicated Instance default trunks. I do not send premises-originated calls to cloud PSTN. I do not collapse Table 5. [cite:1] [cite:3]

What you will not say. You will not invent a peer-SBC priority command.
