00 · Header

T7 · SIP, routing, and queues

SIP Trace Reading Lab

This lab is how you read a Webex Calling dial-plan or Cloud Connected PSTN failure without inventing a ladder. Start in Verify Call Routing. If a media session exists, open Monitoring → Troubleshooting and separate a Cloud Connected PSTN hop from a Local Gateway hop. The PSTN party’s receive metrics are absent because they are not sent to the Webex Calling cloud. Gateway debugs stay in T7-R01.

Room T7-R07 Version v0.1 last-verified: 2026-10-14 Difficulty L3 Est. time 70–90 min Prereq T2-R03, T7-R01 Reading 21 min

Key takeaways

  • Cloud PSTN, Cisco Calling Plan or Cloud Connected PSTN, is only for Webex Calling users. Premises-originated calls cannot use it. [cite:1]
  • Verify Call Routing shows permissions, fraud prevention, digit patterns, call intercept, and translation patterns. Cisco Calling Plan customers and other customers do not share one menu path. [cite:1]
  • CCP numbers are stored in Control Hub as +E.164. The country list lives on the global-availability page the voice-channel article names, and that list changes. [cite:2]
  • Off-net media through a Cloud Connected PSTN provider is a different hop from off-net media through a Local Gateway. PSTN-side end-to-end and receive metrics are not in the cloud view. [cite:3]

01 · Executive summary

Five lines, then why it matters

  • A dial plan is global for the enterprise. It chooses a trunk or a route group for matching patterns, for every user, regardless of location. [cite:1]
  • If the caller is still a premises user, stop. Cloud PSTN will not take that call. Give them a premises path or move the user. [cite:1]
  • Run Verify Call Routing before you open a packet capture. Pick the call source, enter the number or URI, and read the routing result. [cite:1]
  • When the call connected and quality is the complaint, Monitoring → Troubleshooting keeps the past 21 days and shows whether the hop was CCPP or the Local Gateway. [cite:3]
  • Webex Contact Center CCP uses its own location. Do not put endpoint devices in that same location. Outbound premises patterns are a separate dial plan. [cite:2]
Why it matters. Interviewers ask “walk me through a CCP call that fails.” The honest walk is user type, +E.164, the dial plan, Verify Call Routing, then the hop view. A missing PSTN receive stream is what the troubleshooting article says you will see. It is not proof the phone is broken.

03 · Core concepts

Rules that change the trace

Cloud Connected PSTN

n0xb944: choose it when you want a cloud PSTN path and no local hardware, then select a CCP provider. Cloud PSTN, whether Cisco PSTN or Cloud Connected PSTN, provides PSTN access for Webex Calling users. Calls that originate from premises users cannot access cloud PSTN. [cite:1]

Dial plan

Dial plans route calls to on-premises destinations by trunks or route groups. They are configured globally for the enterprise and apply to all users, regardless of location. The routing choice is the trunk or route group for patterns that match. A dial pattern represents on-premises extensions. [cite:1]

+E.164 on CCP

The voice-channel article: CCP providers are provisioned for +E.164, for DID and toll-free. When you configure those numbers in Control Hub, they are saved in +E.164. Webex Calling does the same by default for Cloud Connected PSTN or Local Gateway. The article also says CCP provides connectivity in over 65 countries through certified providers, and it points the country and provider list at the Webex global-availability page. [cite:2]

Contact-center location

Webex Contact Center PSTN needs its own location. Cisco does not support endpoint devices in that same Webex Calling location. The article says placing endpoints there might result in unexpected overage charges on the contact-center subscription. You may create more than one PSTN location, for example one for CCP and one for a Local Gateway. [cite:2]

Two off-net hops

Off-net via Cloud Connected PSTN Provider: the other party is on the PSTN, and media is relayed through the CCPP. Off-net via Local Gateway: the other party’s media comes through the enterprise, either an enterprise-hosted user or enterprise-provided PSTN. For a PSTN caller into a Webex user, the view shows that user’s client metrics and the media relay, not both parties the way an on-net call can. [cite:3]

Missing PSTN metrics

For off-net PSTN through CCPP, the end-to-end experience and the receive stream of the party on the PSTN are not available, because those metrics are not transmitted to the Webex Calling cloud. The Local Gateway section says the same about the party called from the local gateway. Hop quality for CCPP or local gateway is collected from the Webex Calling cloud, not from the PSTN endpoint. [cite:3]

What this room will not draw

The troubleshooting article’s contents list a SIP call diagram. The body used here documents the hop view, the call summary, and refusal and failure codes. Read the diagram on the call you opened in Control Hub. T7-R01 keeps gateway debugs. Do not paste a sample ladder from memory.

05 · Flow

Order of the lab

  1. Name the user. If the call starts on a premises PBX user, cloud PSTN is the wrong path. [cite:1]
  2. Open the location’s PSTN connection. For CCP, Connect Type is Cloud Connected PSTN. Read the numbers under Calling → Numbers and confirm +E.164. [cite:2]
  3. If the destination is on-premises, open the dial plan. It is global. The routing choice is a trunk or a route group. For contact-center outbound premises calls the voice article uses Calling → Call Routing → Dial Plans. [cite:1] [cite:2]
  4. Run Verify Call Routing with the real call source and the real number. Read permissions, fraud prevention, digit patterns, intercept, and translation before you blame the carrier. [cite:1]
  5. If the result says the call should leave, and a media session existed, open Monitoring → Troubleshooting. Confirm CCPP versus Local Gateway. [cite:3]
  6. Hover Refusal or Failure. UnassignedNumber, NoRouteToDestination, and LocalGatewayLoop are the codes to say out loud. Permission and intercept refusals match what Verify Call Routing already displays. [cite:3]
  7. If Troubleshooting is empty, the session may never have reached a Webex Calling-registered endpoint. Continue on the gateway with T7-R01. Do not wait 21 days for a hop that was never created.
Orientation only. A Microsoft Teams dial plan and an Amazon Connect contact flow use different consoles. Compare the Webex pattern with the other product’s own normalization rule. A match in one is not a match in the other.

06 · Config

Clicks the articles print

  • Verify Call Routing: Services → PSTN & Routing → Gateway configurations, then Verify Call Routing. Cisco Calling Plan customers use Services → Calling → Call Routing for the same tool. [cite:1]
  • Call source: cloud user, workspace, virtual line, or premises trunk. Enter a number or URI. See Routing Result. [cite:1]
  • Create a dial plan after the trunk or route group exists. Name it, choose the routing choice, and add patterns. Bulk add is a CSV from the dial plan’s Actions menu. [cite:1]
  • Unknown-number handling: Standard Behavior is the default and the one the article recommends when dial plans exist. Legacy Behavior is for old local-gateway behavior and is not recommended once dial plans are in use. [cite:1]
  • Caller ID format on that same premises setting: +E.164 uses the external calling line ID. ESN uses the internal calling line ID. [cite:1]
  • Contact-center CCP: create the PSTN location, Connect Type Cloud Connected PSTN, add the provider’s numbers, then confirm them under Calling → Numbers in +E.164. [cite:2]
  • Contact-center outbound premises dial plan: Calling → Call Routing → Dial Plans → Create Dial Plan. Name, Routing Choice, Patterns, Save. The article’s sample range is an example of a premises block. Replace it with the numbers you actually own. [cite:2]
  • Troubleshooting: sign in to Control Hub and go to Monitoring → Troubleshooting. The view covers the past 21 days. [cite:3]
  • Before you finish a contact-center PSTN build, place an inbound test call and an outbound test call on the option you chose. [cite:2]
