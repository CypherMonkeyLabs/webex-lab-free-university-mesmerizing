00 · Header

T8 · Flows, integrations, and the current product

Flow Designer Essentials

Flow Designer is how Webex Contact Center routes a live call: activities on a canvas, a main flow, and optional event flows. Publish stays dark until validation is on and the errors are gone. This room is the multi-tenant product. It is not the Enterprise script tool.

Room T8-R01 Version v0.1 last-verified: TODO Difficulty L2 Est. time 80–100 min Prereq T3-R01 Reading 14 min

Key takeaways

  • Flow Designer routes real-time calls. You choose activities, including how agents are assigned, from a drag-and-drop library. [cite:1]
  • Start Flow is already on the main canvas. You cannot delete it. It is the event that triggers the flow. [cite:1]
  • Validation is off by default, so errors stay hidden. With the toggle off, Publish stays disabled. After you turn validation on, Publish stays disabled until every error is fixed. [cite:1]
  • Get Queue Info returns position in queue and estimated wait time. Success needs both values positive. If skills are assigned in the flow on a team-assignment queue, EWT is always −1, and the Insufficient Information branch is the one that still has a valid PIQ. [cite:1]

01 · Executive summary

Five lines, then why it matters

  • Start Flow is already on the main canvas. You cannot delete it. It is the event that triggers the flow. [cite:1]

  • The same article prints two ways to open flows: Services → Contact Center → Flows, and Contact Center → Customer Experience → Flows. Do not pick one and call the other wrong. [cite:1]
Why it matters. A flow that publishes nothing is often just the validation toggle. A flow that treats EWT −1 as “the queue is empty” will mis-route skill queues. The simulator on the Labs page copies these rules. It is not a tenant.

03 · Core concepts

Rules that change what you click

Start Flow

It is on the main canvas by default. You cannot delete it. It indicates the event that triggers the flow and controls how the flow can be used. [cite:1]

Event flows

They are asynchronous to the main flow. You cannot predict when the system triggers one. They are optional extensions of the main flow. [cite:1]

Validation and Publish

The validation toggle is off by default, so errors do not appear. If it is off, Publish stays disabled. After you enable validation, Publish remains disabled until you resolve all errors. [cite:1]

DNIS on a transfer to an entry point

The destination number is presented as NewPhoneContact.DNIS. If the entry point is configured with an E.164 number only, national dialing is converted: the article’s example is 5550101234 presented as +15550101234. If the entry point has both an E.164 number and an extension, DNIS is always the E.164 number. Do not assume one format unless the entry point’s numbering guarantees it. [cite:1]

Not WxCCE scripting

This article is Webex Contact Center. T4 does not treat Flow Designer as the Enterprise script tool. [cite:1]

04 · Ecosystem

Activities and the systems beside them

Flow Designer
The drag-and-drop surface that routes real-time calls and decides what happens at each stage, including how agents are assigned. [cite:1]
Start Flow
Default activity on the main canvas. Cannot be deleted. Names the triggering event. [cite:1]
Event flow
Optional, asynchronous, not predictable from the main path. [cite:1]
Get Queue Info
Returns the caller’s position in queue (PIQ) and estimated wait time (EWT), plus other output variables. [cite:1]
EWT −1
The value Get Queue Info always returns for queues with team assignment and skills assigned in the flow. EWT does not apply there. [cite:1]
Insufficient Information
The branch when PIQ is valid and EWT is −1. You can use PIQ. EWT was not calculated. [cite:1]
Success branch
Both EWT and PIQ come back positive. [cite:1]
Queue priority
An integer variable from 1 through 9. Outside that range, the default priority is 10. [cite:1]
Fallback queue
Used only when a queue variable fails to return a valid queue ID. [cite:1]
NewPhoneContact.DNIS
The DNIS presented to the receiving entry-point flow after a transfer. Format depends on how that entry point is numbered. [cite:1]
BRE Request
A Flow Designer utility activity. The Business Rules Engine guide says you can build a flow that invokes it. [cite:2]
QueueToAgent
Named in the multi-tenant architecture article as voice, direct to an agent id. It is a different sentence from this room’s Queue Contact activity. [cite:3]

05 · Flow

A queue treatment you can defend

  1. Open flows with either printed cascade: Services → Contact Center → Flows, or Contact Center → Customer Experience → Flows. Functions are under Services → Contact Center → Customer Experience → Functions. [cite:1]
  2. Leave Start Flow in place. Add Play Message or Menu only if the treatment needs them. [cite:1]
  3. Add Get Queue Info before you promise a wait announcement. Branch Success only when EWT and PIQ are both positive. Branch Insufficient Information when PIQ is valid and EWT is −1. [cite:1]
  4. If the queue is team-based and the flow assigns skills, plan on EWT −1. Do not announce a calculated wait. [cite:1]
  5. Queue Contact can use a static queue or a variable. If you use a variable, set a fallback queue for an invalid ID. Priority 1–9; anything else becomes 10. [cite:1]
  6. If you need an HTTP Request after Queue Contact, put Play Message or Play Music between them. [cite:1]
  7. Turn validation on. Fix every error. Only then does Publish leave the disabled state the article describes. [cite:1]

09 · Self-question ladder

L1What does Flow Designer route?

Real-time calls, including how agents are assigned and what happens at each stage. [cite:1]

L1Can you delete Start Flow?

No. It is on the main canvas by default. [cite:1]

L2What is true while the validation toggle is off?

Errors do not appear, and Publish stays disabled. [cite:1]

L2When does Success fire on Get Queue Info?

When both EWT and PIQ are positive. [cite:1]

L2When does Insufficient Information fire?

PIQ is valid and EWT is −1. [cite:1]

L2When is EWT always −1?

Queues with team assignment and skills assigned in the flow. EWT does not apply. [cite:1]

L3What priority is used if the variable is 12?

10. Only 1 through 9 are in range. [cite:1]

L3When is the fallback queue used?

Only if the queue variable fails to return a valid queue ID. [cite:1]

L3What do you insert between Queue Contact and HTTP Request?

A short delay such as Play Message or Play Music. Otherwise the request may not retrieve the data. [cite:1]

L3A caller dials extension 1234 and the entry point also has an E.164 number. What DNIS should the flow expect?

The E.164 number, not the extension. [cite:1]

L4Name both flow-opening cascades in the article.

Services → Contact Center → Flows, and Contact Center → Customer Experience → Flows. [cite:1]

13 · Interview

“Flow Designer is the Webex Contact Center canvas, not the Enterprise script tool. Start Flow stays. I do not publish until validation is on and the errors are gone, because Publish is disabled in both of those earlier states. Get Queue Info’s Success branch needs a positive wait and a positive position. If the queue is team-based and the flow assigns skills, estimated wait is always −1 and I use the Insufficient Information branch. Priority outside 1 to 9 becomes 10. A variable queue needs a fallback. I never chain HTTP Request directly onto Queue Contact. If an entry point has both an E.164 number and an extension, DNIS is the E.164 number. The help article itself prints two different menu paths, so I cite both.”
