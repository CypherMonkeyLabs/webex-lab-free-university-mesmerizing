00 · Header

T8 · Flows, integrations, and the current product

CRM Integrations

Salesforce, Dynamics 365, and ServiceNow each get a Version 2 connector that launches the Webex Contact Center desktop inside that CRM. The three articles share the chat-and-email exclusion, the dial-plan DN gap, and the tenant-timeout gap. They do not share a browser list, a CIF version, or a campaign-field pair.

Room T8-R04 Version v0.1 last-verified: 2026-10-14 Difficulty L3 Est. time 70–90 min Prereq T3-R04, T8-R01 Reading 23 min

Key takeaways

  • Digital channels such as chat and email are not supported with CRM connectors. That sentence applies to all CRM integrations using these connectors. [cite:1]
  • Salesforce is Lightning only, and only on Development, Enterprise, and Ultimate editions. WebRTC there is Firefox and Chrome. Microsoft Edge is not supported. [cite:1]
  • Dynamics uses CIF 1 for a single-session app and CIF 2 for a multi-session app. On-premises Dynamics is not supported. WebRTC there is Edge and Chrome. [cite:2]
  • The gadget does not enforce Validate using Dial Plans. The tenant Desktop Inactivity Timeout does not log the connector out. Use the Desktop Profile Desktop Timeout. [cite:1]

01 · Executive summary

Five lines, then why it matters

  • Each connector launches Desktop inside the CRM. You do not create a new Webex App for the install. [cite:1] [cite:2] [cite:3]
  • Chat and email stay on Connect and the digital desktop. The connector articles say those channels are unsupported here, for every CRM that uses these connectors. [cite:1]
  • Salesforce screen pop is for inbound calls. Internal and outbound calls search and show data in the connector, and no screen pops. [cite:1]
  • A Dynamics screen pop of a CRM record needs a relative URL. If recordType and crmId are both present, the defined URL is ignored. [cite:2]
  • Campaign modes named on these pages are Predictive and Progressive. Salesforce’s required business field is CAMPAIGN_CRM_ID. Dynamics and ServiceNow also require CAMPAIGN_CRM_TABLE. [cite:1] [cite:2] [cite:3]
Why it matters. Interviewers say “CRM integration” as if one gadget fits three consoles. The honest answer names the edition, the CIF version, the browser, and the field that is missing on Salesforce. T3-R04 already has the desktop. T8-R03 already has Connect. This room is the install that sits between them.

03 · Core concepts

Rules that change the drawing

CRM connector

Integrating Webex Contact Center with Salesforce, Dynamics, or ServiceNow launches Desktop from inside that console. The articles say you do not need to create a new Webex App. [cite:1] [cite:2] [cite:3]

Chat and email

Digital channels such as chat and email are not supported with CRM connectors. The Salesforce article says this applies to all CRM integrations using these connectors. Dynamics and ServiceNow print the same sentence. Read the digital conversation in Connect or on the desktop. [cite:1] [cite:2] [cite:3]

Salesforce editions and UI

Classic mode is not supported. Use a Lightning app from App Manager. The connector is available exclusively for Development, Enterprise, and Ultimate editions. It is not available in Group and Professional editions. Agents need an Access Profile that allows Wrapup Options. [cite:1]

CIF

Dynamics uses Microsoft’s Channel Integration Framework. A single-session Dynamics app requires CIF version 1. Multi-session apps require CIF version 2. Omnichannel for Customer Service and Customer Service Workspace are the multi-session examples. Customer Service Hub is the single-session example. On-premises Dynamics is not supported. Install the framework before the connector. [cite:2]

ServiceNow workspace

The legacy Agent Workspace is no longer supported starting with the Xanadu edition. The connector is designed for the modern Agent Workspace. The article tells customers to migrate so they keep the integration on Yokohama, Xanadu, or newer. Update sets are only for developer instances. Enterprise-licensed instances install Cisco Webex Contact Center from the ServiceNow store. Mixing the enterprise-licensed app with a developer sandbox is not recommended. [cite:3]

Screen pop is not one behavior

On Salesforce, screen pop is only for inbound calls. A softphone layout without the Name field shows an unknown error instead of the record name. On Dynamics, a Screen Pop node in the flow can open a record when the URL is relative. recordType is the table name, such as incident. crmId is the record identifier. If both keys are present, the defined URL is ignored. [cite:1] [cite:2]

Two timeouts

Automatic logout uses a custom value on the Desktop Profile Desktop Timeout. The global Tenant Settings Desktop Inactivity Timeout does not affect the CRM connector and will not log the agent out when that inactive duration is reached. All three articles print that limitation. [cite:1] [cite:2] [cite:3]

05 · Flow

Order of operations

  1. Confirm the CRM edition and UI before you download a package. Salesforce must be Lightning and one of Development, Enterprise, or Ultimate. Dynamics must be online. ServiceNow must be the modern workspace. [cite:1] [cite:2] [cite:3]
  2. Install the framework that console requires. Dynamics needs Channel Integration Framework first. ServiceNow needs the Openframe plugin. Salesforce imports the call-center XML after the package. [cite:1] [cite:2] [cite:3]
  3. Set the region. The shared names are us1, ca1, eu1, eu2, anz1, jp1, and sg1. Put that value in the call center, the channel custom parameter, or the Openframe key the article shows. [cite:1] [cite:2] [cite:3]
  4. Give the agent the role or call-center membership the article names, then confirm the phone icon. Salesforce hides the phone until call-center settings are saved and users are added. [cite:1]
  5. Allow Desktop on the desktop profile and set webRtcDomain for that tenant before you test WebRTC. Use the browser list for that CRM. [cite:1] [cite:2]
  6. Place a test call through the connector and confirm sign-in and call handling. The articles’ verification step is that test, not a chat transcript. [cite:1] [cite:3]

06 · Config

Clicks the articles print

  • Salesforce package: Install for Admins Only. Sandbox uses the sandbox login URL, then you install again in production with Install in Production. [cite:1]
  • Softphone layout: Feature Settings, Service, Call Center, Softphone Layouts. Check Is Default Layout. Choose the objects that trigger lookup and screen pop. [cite:1]
  • Call center file: download OpenCTI.callCenter-meta.xml from the webex-contact-center-crm-connectors repository the article links. Import under Setup, Call Center, Call Centers. Set WxCC Region and save. [cite:1]
  • Salesforce compatibility mode defaults to Lightning. The table says not to change it. Softphone defaults are height 550 and width 400, and the table allows any height and any width. [cite:1]
  • Subject template placeholders that are replaced are {direction} and {activityDatetime}. CAD variables are not supported in that template. Object field mappings allow a single CAD variable per field. Combinations and fixed text mixed into one value are not supported. [cite:1]
  • Dynamics CIF 2: Customer Service admin center, Workspaces, Agent experience profiles. Name Webex Contact Center. Unique name wxcc_appprofile. Channel provider unique name wxcc_channelProvider_Dynamics. Enable outbound Yes. Channel order 1. API version 2. [cite:2]
  • Dynamics desktop URLs: desktop.wxcc-us1.cisco.com, desktop.wxcc-eu1.cisco.com, desktop.wxcc-eu2.cisco.com, desktop.wxcc-anz1.cisco.com, desktop.wxcc-jp1.cisco.com, and desktop.wxcc-sg1.cisco.com with the trailing slash the article prints on Singapore. Add *.dynamics.com to the content-security allow list. [cite:2]
  • ServiceNow developer path: All, System Definition, Plugins, install Openframe. Import updateSet.xml, preview, commit. Assign x_caci_crm_wxcc.CC Agent, sn_openframe_user, and interaction_agent. [cite:3]
  • ServiceNow enterprise path: install Cisco Webex Contact Center from store.servicenow.com. The article also names a legacy package on that store. Update sets stay on developer instances. [cite:3]
  • ServiceNow WebRTC also needs the property sn_openframe.cross.origin.access set to microphone *;autoplay;speaker-selection. [cite:3]
  • DN options in Control Hub, Desktop Profiles, Voice Channel Options: Unrestricted, Provisioned DN, or Validate using Dial Plans. The gadget does not enforce the dial-plan option. [cite:1]
  • Agent-state sync with the Webex App is enabled in desktop tenant settings or in the desktop profile collaboration settings. Agents already signed in refresh the browser to apply it. [cite:1]

09 · Self-question ladder

L1What does the connector launch?

Desktop, from inside Salesforce, Dynamics, or ServiceNow. [cite:1]

L1Which channels are excluded?

Chat and email, on every CRM integration that uses these connectors. [cite:1]

L2Which Salesforce editions qualify?

Development, Enterprise, and Ultimate. Group and Professional do not. [cite:1]

L2Is Salesforce Classic supported?

No. Lightning from App Manager. [cite:1]

L2Which browsers does Salesforce name for WebRTC?

Firefox and Google Chrome. Edge is not supported. [cite:1]

L2Which browsers does Dynamics name for WebRTC?

Microsoft Edge and Google Chrome. [cite:2]

L3When is CIF 2 required?

Multi-session apps, such as Omnichannel for Customer Service or Customer Service Workspace. A single-session app such as Customer Service Hub uses CIF 1. [cite:2]

L3Is on-premises Dynamics supported?

No. [cite:2]

L3What does Validate using Dial Plans do inside the gadget?

Nothing in the current gadget. The article says the setting has no effect. [cite:1]

L3Which timeout logs the connector out?

A custom Desktop Profile Desktop Timeout. The tenant Desktop Inactivity Timeout does not. [cite:1]

L4Which campaign fields does Salesforce require?

CAMPAIGN_CRM_ID. FirstName and LastName are optional. The modes are Predictive and Progressive. [cite:1]

L4What extra campaign field do Dynamics and ServiceNow require?

CAMPAIGN_CRM_TABLE, along with CAMPAIGN_CRM_ID. [cite:2] [cite:3]

L4What happens when a Dynamics screen pop sends both recordType and crmId?

The defined URL is ignored. The URL must be relative to open a Dynamics record. [cite:2]

L5Why can the same agent fail WebRTC in Edge on one CRM and succeed on another?
